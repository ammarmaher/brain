# Falcon Component Library Structure

> The full anatomy of `libs/falcon-ui-core/` — Stencil components + Angular wrappers + Tailwind class-maps + their token contracts. Each "component" in Falcon is actually 4-5 cooperating artifacts across 3 libraries. This note maps every artifact for every component.

## What a "Falcon component" actually is

A single Falcon component (e.g., `falcon-button`) is the sum of these artifacts:

```
1. Stencil Shadow component       libs/falcon-ui-core/src/components/falcon-button/falcon-button.tsx
2. Stencil Light (-tw) component  libs/falcon-ui-core/src/components/falcon-button-tw/falcon-button-tw.tsx
3. Stencil scoped CSS             libs/falcon-ui-core/src/components/falcon-button/falcon-button.css
4. Tailwind class-map TS          libs/falcon-ui-core/src/tailwind/button-tailwind-classes.ts
5. Angular wrapper                libs/falcon-ui-core/src/angular-wrapper/components/falcon-button/
                                    └── falcon-angular-button.component.ts
6. Per-component token contract   libs/falcon-ui-tokens/src/components/button.tokens.css
7. (Brain Outputs SoT dossier)    Brain Outputs/understanding/frontend/components/falcon-button/
                                    OVERVIEW.md · API.md · USAGE.md · GAPS_AND_UPGRADES.md · TOKENS.md · DECISION.md
```

**Each consumer (Angular template / React app / Vue app / vanilla HTML) only ever sees the public-facing wrapper + token-override surface — never the internals.**

## Library breakdown

### `libs/falcon-ui-core/src/` (audited 2026-05-20)

| Subfolder | Count | Purpose |
|---|---|---|
| `components/` | **103 directories** | Stencil source — Shadow (`falcon-X`) + Light/Tailwind (`falcon-X-tw`) variants |
| `angular-wrapper/components/` | **62 directories** | Angular wrappers (49 active + variants) |
| `tailwind/` | **95 `*.ts` files** | Runtime class-string composers — `falconButtonClasses({variant, size})` |
| `configurations/` | small | Component defaults + presets |
| `types/` | small | Shared TypeScript types |
| `utils/` | small | Shared utilities |
| `styles/` | small | Component-internal CSS partials |
| `components.ts` · `define-*.ts` · `index.ts` (+ `.js` + `.d.ts` + maps) | — | **Auto-generated** Stencil aggregators — see [[Falcon Generated Files Rules]] |

### Stencil component layout (103 components)

Each component directory contains:

```
falcon-button/                          ← Shadow component
├── falcon-button.tsx                   ← Stencil TSX template
├── falcon-button.css                   ← Scoped CSS (reads --falcon-button-* tokens)
├── falcon-button.types.ts              ← Public types
├── falcon-button.tests.ts              ← (if exists)
└── readme.md                           ← Auto-generated by Stencil

falcon-button-tw/                       ← Light DOM Tailwind component
├── falcon-button-tw.tsx                ← Uses Tailwind utilities directly
├── falcon-button-tw.css                ← Minimal (component-internal only)
└── readme.md
```

**Shadow vs Light (`-tw`) variants:**
- **Shadow** — `shadow: true`, sealed from global stylesheet, full token isolation, uses scoped CSS that reads `var(--falcon-X)`
- **Light (`-tw`)** — `shadow: false`, cascade-friendly, uses Tailwind utilities inline in TSX

Per the [[Falcon Stencil-to-Angular Bridge]] note, modern components use **Light/`-tw`** so Tailwind utilities cascade in.

### Angular wrapper layout (62 directories — 49 active)

```
angular-wrapper/components/falcon-button/
├── falcon-angular-button.component.ts  ← Wrapper class (signals + CVA + OnPush)
├── falcon-angular-button.component.html (optional — most are inline)
└── index.ts                            ← Public export
```

**Per [[Falcon Angular Wrapper Pattern]]:** wrappers map Angular APIs to Stencil props/events/slots. They DO NOT redesign components.

### Tailwind class-map layout (95 `*.ts` files)

```
tailwind/
├── button-tailwind-classes.ts
├── input-tailwind-classes.ts
├── accordion-tailwind-classes.ts
├── avatar-tailwind-classes.ts
├── badge-tailwind-classes.ts
├── … (90+ more)
└── shared/                              ← Cross-component helpers
```

Each file exports a function like:

```typescript
export function falconButtonClasses(opts: {
  variant?: 'primary' | 'secondary' | 'danger';
  size?: 'sm' | 'md' | 'lg';
  disabled?: boolean;
  loading?: boolean;
}): string {
  return [
    'bg-falcon-teal-700 hover:bg-falcon-teal-800',
    opts.variant === 'danger' && 'bg-falcon-red-500 hover:bg-falcon-red-600',
    opts.size === 'sm' && 'px-2 py-1 text-sm',
    opts.disabled && 'opacity-50 cursor-not-allowed',
  ].filter(Boolean).join(' ');
}
```

**Critical rule:** every class literal in these strings must appear statically in the file so [[Tailwind Source Detection]] picks it up. Runtime concatenation that ONLY produces a never-seen literal requires `@source inline("...")` safelist (P1-38 — should be auto-generated).

### `libs/falcon-ui-tokens/src/components/` (51 token contract files)

Each component has ONE `.tokens.css` file declaring CSS-var slots scoped to component hosts:

```css
/* button.tokens.css */
:where(falcon-button, falcon-button-tw, falcon-angular-button, .falcon-button, [data-falcon-button]) {
  --falcon-button-bg-default: var(--falcon-color-primary);
  --falcon-button-bg-hover: var(--falcon-color-primary-hover);
  /* … */
}
```

**Per [[Falcon Tailwind Theme]] / [[Tailwind Mental Model]]:** these are Layer 3 contracts. They MUST chain through Layer 2 semantic tokens, not raw Layer 1 primitives. **Drift documented in [[Tailwind Falcon Alignment Scorecard]] Finding 1.**

| **Deprecated** (kept for back-compat) | 2 | falcon-dialog, falcon-toast |

| **TOTAL** | **60 active components + shared-directives** | |

Plus duplicates within `components/` (103 dirs vs 60 components) because each modern component has both `falcon-X` (Shadow) AND `falcon-X-tw` (Light) sub-folders.

## Consumer journey (Angular app perspective)

```
Angular app template
  <falcon-angular-button variant="primary" size="lg" (falconClick)="onSave()">
    <span slot="label">Save</span>
  </falcon-angular-button>
    │
    ▼
Angular wrapper (libs/falcon-ui-core/src/angular-wrapper/components/falcon-button/)
  - Maps [variant] → Stencil @Prop variant
  - Maps (falconClick) → Stencil @Event falconClick
  - Forwards <ng-content select="[slot=label]"> → Stencil <slot name="label">
  - Wraps with OnPush + CVA if input-family
    │
    ▼
Stencil Light (-tw) component (libs/falcon-ui-core/src/components/falcon-button-tw/)
  - TSX renders <button class={falconButtonClasses({variant, size, ...})}>
  - Tailwind class-map (libs/falcon-ui-core/src/tailwind/button-tailwind-classes.ts) returns class string
    │
    ▼
Tailwind utilities resolve via @theme block in SSOT
  - bg-falcon-teal-700 → CSS rule: background-color: var(--color-falcon-teal-700)
  - --color-falcon-teal-700 resolved via cascade (theme/dark/density/rtl overrides)
    │
    ▼
Browser paints with resolved value
```

## Multi-framework consumer journey (architecture-neutral)

| Framework | Consumer pattern | What loads |
|---|---|---|
| **Angular** (current) | `<falcon-angular-button>` (wrapper) | Tailwind utility + Stencil Light component + token contract |
| React (future) | `<FalconButton>` (placeholder — see [[Falcon React Wrapper Future Pattern]]) | Same Stencil component, no Angular wrapper |
| Vue (future) | `<FalconButton>` (placeholder — see [[Falcon Vue Wrapper Future Pattern]]) | Same Stencil component, no Angular wrapper |
| Vanilla HTML | `<falcon-button-tw>` (raw Web Component) | Stencil Light component directly |

**One Stencil source → 4 framework consumers, same visual contract.**

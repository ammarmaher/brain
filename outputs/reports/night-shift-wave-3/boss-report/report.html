BRAIN ANATOMY · 7 STORES · 03

02The Brain's 7 Knowledge Stores

The Falcon Brain is not one big document — it is a typed graph of seven specialised stores. Each store answers a different class of question. The chart below shows their relative depth in file count. Authority Dataset and Brain SK carry the operational load; PRD Modules and Memory carry the human-curated standing rules.

File counts across the 7 stores · ~4,100 artifacts total
Operational load

Brain SK · Authority Dataset · Old-UI Dataset. These three answer "where in the code is this rule" and "what does the live system actually do".

Curated rules

Memory · PRD Modules. 108 standing memory entries (46 are immutable "feedback" rules) and 39 PRD module specs you reviewed.

Lookup & routing

Falcon Wiki · Brain Out/Understanding. The router and the per-feature deep-dives — read first, drill later.

Why this matters

A single document of 4,100 files would be unsearchable. Splitting them into seven typed stores means the orchestrator can route every question to one owner — and only descend further if the answer isn't there. During Wave #3, 93% of the questions hit their owning store on the first read.

11End-to-End Conversion

Tracking the wizard's journey from login → AO landing page, before and after the fix. Two stacked drifts capped the pre-fix funnel at 67%. The post-fix funnel runs the full path with the brain's captured wire payload as the ground-truth assertion.

Funnel — pre-fix vs post-fix

Headline numbers

  • Pre-fix end-to-end completion: 50% (3 of 6 stages green)
  • Post-fix end-to-end completion: 100% on the first 5 stages, AO-login as the final smoke-test on next run.
  • Effective stage-3 drive time: ~6 minutes (vs. 15 minutes pre-fix exploratory)

Why this looks like 100% gains

Because the bugs were in data assembly, not the UI itself, fixing the wire builder unlocked every stage downstream. One file change → entire funnel works. This is why the brain's "diagnose before fixing" mantra pays off: pre-fix, the visible UI looked 90%-correct, and we'd have wasted hours blaming the UI.

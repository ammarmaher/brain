# falcon-calendar — Integration & Validation Layer

> Layer 3 of 3. UI layer → `OVERVIEW.md` etc. Business layer → `BUSINESS.md`.

## Owning backend module(s)
**None — the component is presentational.** It owns no data and calls no endpoint. It receives a date string in, emits a date string out. The *meaning* of that date (and any min/max/disabled policy) is owned by whatever flow embeds it:
- `[MEMORY]` **Commerce** — when used for a service pricing-change effective date (apps/services tab), the bounds and the resulting date are Commerce-owned (`SetPriceType` effective-date rule).
- `[INFERRED]` Any other host flow owns its own date semantics.

## Backend wiring
| Endpoint | Method | Backend module | DTO (req / resp) | Gateway | Notes |
|---|---|---|---|---|---|
| — | — | — | — | — | `[CODE]` `falcon-calendar.tsx` — no HTTP. The grid is computed entirely in-browser by `buildMonthGrid()` (`falcon-calendar.tsx:153`). |

The host flow does the wiring: it fetches whatever data sets `min` / `max` / `disabledDates`, binds `[value]`, and on `(valueChange)` writes the ISO string into its own request payload.

## Validation rules (V-*)
| V-rule | Field | Trigger | Error code / message |
|---|---|---|---|
| `[CODE]` Out-of-bounds guard | the day cell | click a cell below `min` / above `max` | no error — cell is rendered `isDisabled` and the click is swallowed (`falcon-calendar.tsx:102-107`). |
| `[CODE]` Excluded-date guard | the day cell | click a date in the `disabledDates` array / matching the predicate | same — silently non-clickable, slash overlay shown. |
| `[INFERRED]` Required-date | the bound form control | submit with `value === null` | not the calendar's job — the host form control / `validations.ts` raises "required". The calendar has no CVA so it cannot mark itself invalid. |
| `[MEMORY]` `InvalidEffectiveDateForPeriodicPricingChange` | effective date | backend rejects a date that violates the renew-day clamp | server-side (Commerce). The calendar cannot pre-validate this — the host flow should pass a matching `disabledDates` predicate to prevent it client-side. |

## PES keys gating this component
| PES key | Action | Effect when denied |
|---|---|---|
| `[INFERRED]` (inherited) | — | The calendar has no PES key. It inherits the gate of the *field* it renders: where the host flow's PES resolution denies edit, the parent passes `[disabled]="true"` and the whole grid freezes. |

## State / signal pattern
`[CODE]` `falcon-calendar.component.ts`
- **No `ControlValueAccessor`.** The Angular wrapper `FalconAngularCalendarComponent` does NOT implement CVA. Reactive-Forms / `[(ngModel)]` binding is **not** supported on this wrapper — bind `[value]` + `(valueChange)` two-way, or `(falconChange)` for the full `FalconCalendarChangeDetail`.
- `disabledDates` is pushed as a **JS property**, not an attribute — `syncProps()` (`falcon-calendar.component.ts:72-79`) runs on `ngAfterViewInit` + every `ngOnChanges` and assigns `el.disabledDates = this.disabledDates`. Passing it as `[attr.disabledDates]` (a string) silently fails.
- Stencil internal state: `viewDate`, `focusedDate`, `resolvedId` are `@State()` (`falcon-calendar.tsx:65-67`). `value` is `@Prop({ mutable:true })` — the component mutates its own value on day-click then emits.
- `[CODE]` `@Watch('value')` (`falcon-calendar.tsx:80-84`) re-syncs `viewDate` whenever the bound value changes — so a parent that programmatically sets the date also moves the visible month.

## Skeleton ↔ app-wrapper layering
- **Stencil skeleton** — `<falcon-calendar>` (Shadow DOM, `falcon-calendar.tsx:37-41`) and `<falcon-calendar-tw>` (Light DOM Tailwind variant). Pure presentational; the grid is generated by `buildMonthGrid()` in `falcon-calendar.utils.ts`.
- **Angular wrapper** — `<falcon-angular-calendar>` (`falcon-calendar.component.ts`). Renders BOTH skeletons behind a `useTailwind` switch (`@if` in the HTML template); `ngOnInit` lazily registers the element via `defineFalconTwComponent('falcon-calendar')`.
- Per `feedback_library_skeleton_app_api`: the wrapper does no data fetching — the host app/state layer supplies all bounds and the value.

## Integration gotchas
- `[CODE]` **No popover-portal.** Unlike `<falcon-date-picker>`, this is an inline grid — it does NOT use `popover-portal.ts`, has no `appendTo`, and cannot suffer the transformed-ancestor positioning bug documented in `_LEARNINGS_POPOVER_PORTAL_PATTERN.md`. If you need the popover behavior, use `<falcon-angular-date-picker>` which embeds this grid in a portaled panel.
- `[CODE]` **`disabledDates` must be a stable reference.** `syncProps()` re-assigns on *every* `ngOnChanges`; if the predicate function is re-created each change-detection pass, the Stencil prop churns. Keep the predicate identity stable (declare it once on the component class) — see `GAPS_AND_UPGRADES.md` G7.
- `[CODE]` **Stencil `@Method`s exist; wrapper proxies do not (G5).** The Stencil tags expose `@Method()` `setValue(v)` and `navigate('prev-month'|'next-month'|'prev-year'|'next-year')` (`[CODE]` `falcon-calendar.tsx:86-97`, mirrored on `-tw` :97-108). `FalconAngularCalendarComponent` does NOT surface them — an app must call them on the native element ref. (API.md now documents this accurately as of the B07 refresh.)
- `[CODE]` **15 wrapper `@Input`s, not 11** (`falcon-calendar.component.ts:64-82`): the original 11 + `disabledIconEnabled`/`disabledIconColor`/`disabledIconWidth`/`disabledIconHeight` (the 2026-05-15 disabled-slash overlay). `prevMonthAriaLabel` / `nextMonthAriaLabel` exist on the Stencil tags (`falcon-calendar.tsx:51-52`) but are NOT forwarded by the wrapper (a11y GAP). API.md corrected in the B07 refresh.
- `[CODE]` **Keyboard grid nav is IMPLEMENTED** (`falcon-calendar.tsx:109-145`, mirrored on `-tw` :120-155): Arrows (±1d/±7d), Home/End (week), PageUp/Down (±month), Shift+PageUp/Down (±year), Enter/Space to select. Focus moves via `requestAnimationFrame` after the month re-renders (Shadow queries `host.shadowRoot`, `-tw` queries `host`). The prior "verify keyboard nav" hedge is resolved.
- `[CODE]` **`(falconBlur)` is effectively dead.** The wrapper re-emits `falcon-blur` (`falcon-calendar.component.ts:113-116`) and the `@Event` is declared (`falcon-calendar.tsx:71-72`), but neither Stencil tag ever calls `this.falconBlur.emit(...)` in the inspected source — so the output never fires. Do not rely on `(falconBlur)`.

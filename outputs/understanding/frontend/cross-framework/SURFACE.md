## 1. `@falcon/ui-react` — barrel & exports

`[CODE]` `src/index.ts:4` — `export * from './components';`. The barrel is a one-line re-export; **all surface lives in the generated `components.ts`**.

### Per-export shape (generated by `@stencil/react-output-target`)
Each component is a `StencilReactComponent` built via `createComponent({...})`:
```ts
// components.ts:127-138 (FalconAccordion exemplar)
export const FalconAccordion: StencilReactComponent<FalconAccordionElement, FalconAccordionEvents> =
  /*@__PURE__*/ createComponent<...>({
    tagName: 'falcon-accordion',
    elementClass: FalconAccordionElement,
    react: React,
    events: { onFalconChange: 'falcon-change', onFalconExpand: 'falcon-expand', onFalconCollapse: 'falcon-collapse' },
    defineCustomElement: defineFalconAccordion,
  });
```
- **Props** are inherited from the Stencil `elementClass` type (`Falcon*Element` imported from `@falcon/ui-core/dist/components/falcon-*.js`) — the React wrapper does NOT re-declare props; TS infers them. `[CODE]` `components.ts:11-116` (one `import {...defineCustomElement...}` per element).
- **Events** are mapped from React `onFalconX` handler names → the kebab DOM event name (`'falcon-change'`). Components with no events get `Events = NonNullable<unknown>` + `events: {}`. `[CODE]` e.g. `FalconAvatar` `components.ts:197-206`.
- **`defineCustomElement`** is wired per component → tree-shakable lazy element registration (importing `FalconButton` registers only `falcon-button`).
- **`'use client';`** at file top (`:1`) — Next.js React Server Components compat (these are client components).
- **Event-name detail nuance:** most events use kebab DOM names (`'falcon-change'`), but a subset use camelCase DOM event names — `FalconCombobox`/`FalconMultiSelect`/`FalconFilterPanel`/`FalconGridInput`/`FalconDrawer` emit `'falconComboboxFilter'`, `'falconDrawerShow'`, etc. (the wrapper faithfully mirrors whatever the Stencil `@Event()` name is). `[CODE]` `components.ts:402-404` (combobox), `:688-692`-region (drawer in vue equivalent).

### Imported type surface
`components.ts:10` imports **every** `Falcon*CustomEvent` + `Falcon*Detail` type from `@falcon/ui-core` (one giant `import type {...}`) — so consumers get fully-typed event payloads (`onFalconClick={(e: FalconButtonCustomEvent<FalconButtonClickDetail>) => …}`).

### Generation entrypoint (React)
`[CODE]` `stencil.config.ts:47-50`:
```ts
reactOutputTarget({ outDir: '../falcon-ui-react/src', stencilPackageName: '@falcon/ui-core' })
```
Runs in-process during `nx build falcon-ui-core`. Plugin `@stencil/react-output-target@0.7.4`, Stencil `@stencil/core@4.43.4`. `[CODE]` `WAVE-6-REACT-TARGET.md:14-16`.

## 2. `@falcon/ui-vue` — exports

`[CODE]` `src/index.ts` is the generated file directly (no separate barrel). Header banner `:1-3`.

### Module preamble
```ts
// index.ts:4-8
import { defineContainer, type StencilVueComponent } from '@stencil/vue-output-target/runtime';
import type { JSX } from '@falcon/ui-core/types';
import { defineCustomElements } from '@falcon/ui-core/loader';
defineCustomElements();   // ← registers ALL elements eagerly at module load
```
**Key difference vs React:** Vue calls `defineCustomElements()` once at import (eager registration of all 106 elements), whereas React wires `defineCustomElement` per-component (lazy). `[CODE]` `index.ts:8` vs `components.ts:137`.

### Per-export shape (generated by `generate-vue-proxies.cjs`)
```ts
// index.ts:10-27 (FalconAccordion exemplar)
export const FalconAccordion: StencilVueComponent<JSX.FalconAccordion> =
  /*@__PURE__*/ defineContainer<JSX.FalconAccordion>('falcon-accordion', undefined, [
    'items','expandedValues','mode','size','disabled','helperText','errorMessage','showChevron','ariaLabel',
    'falcon-change','falcon-expand','falcon-collapse'      // ← props array (incl. event names)
  ], [
    'falcon-change','falcon-expand','falcon-collapse'      // ← emitted-events array (model/v-on)
  ]);
```
- `defineContainer(tag, modelProp, propsArray, eventsArray)` — the standard `@stencil/vue-output-target` runtime signature.
- **Props array** = every `@Prop()` name (parsed from the `.tsx` decorators by the `.cjs`), PLUS the event names appended (Vue includes events in the attrs list).
- **Events array** = the `@Event()` names (drive `v-on:` / `emits`).
- Type generic `JSX.FalconAccordion` pulled from `@falcon/ui-core/types`.
- The `.cjs` parses decorators via regex, so the props arrays reflect the **literal** Stencil prop set (including `-tw`-only extras like `rootExtraClass`, `wrapperExtraClass`, `appendTo`). `[CODE]` `index.ts:106-115` (avatar-tw adds `rootExtraClass`), `:469` (date-picker-tw adds `appendTo`).

### Generation entrypoint (Vue)
`[CODE]` `WAVE-7-VUE-TARGET.md:27-37` — `libs/falcon-ui-core/generate-vue-proxies.cjs`, called from `build.cjs` after both the clean-build and EMFILE-recovery paths. **`stencil.config.ts` does NOT import or call `vueOutputTarget`** (`Grep 'vue'` on `stencil.config.ts` = 0 hits) — confirming the live generator is the standalone script, not the Stencil plugin. The WAVE-7 doc's `vueOutputTarget({...})` block (`:10-16`) is **stale documentation** (AUDIT F1). The `@stencil/vue-output-target@^0.13.1` package is still a dependency (`package.json:23`) because the `.cjs` emits code that imports `@stencil/vue-output-target/runtime` (`defineContainer`).

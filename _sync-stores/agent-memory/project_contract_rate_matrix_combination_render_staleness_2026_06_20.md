**Symptom:** switch Application/CommChannel → the rate table keeps showing the PREVIOUS combination's values (default should be empty / that combo's own values).

**ROOT CAUSE = render-layer staleness, NOT storage.** [CODE] `contract-details-step.component.ts:187-192` `matrixStructureKey` fingerprints ONLY `priorities::destinations` (value- AND combination-independent). `matrixRows` (`[data]`, 268-278), `matrixColumns`, `destinationHeaders`, and the `mountKick` effect (311-314) ALL depend solely on that key + read `matrix()` untracked. Two different combos almost always share the same shape (any two non-Voice channels, or same channel under different apps → identical 4 priorities × 11 countries), so the key string is byte-identical, the `computed` short-circuits via `Object.is`, `matrixRows` never recomputes, `[data]` ref is unchanged, OnPush table doesn't re-render, and the `<falcon-angular-input-number>` cells keep the old combo's numbers. Header dropdowns DO update (they read `matrix()` directly). The value-independent key was added on purpose to fix "cell input disappears as you type" — it is too aggressive and also suppresses the legitimate re-render on a same-shape combo switch.

**What is CORRECT (verified):** The DATA layer is genuinely per-combination. `rates: ContractRateRow[]` is the flat SoT; every row carries its own `applicationId`+`channelId`. `createRateMatrixForSelection` filters `rates` by `(applicationId,channelId)` (empty when none); `syncRateMatrixIntoRates` drops only the current combo's rows and re-appends — effectively a dictionary keyed by `${applicationId}|${channelId}`. `changeRateSelection` persists-then-reprojects; dropdowns are ONE-WAY `[ngModel]`+`(ngModelChange)` so persist captures the OLD combo safely (binding-direction hazard REFUTED). Save sends ALL combos: `contracts-api.service.ts:389-415 toUpdatePayload` = `syncRateMatrixIntoRates(form.rates, form.rateMatrix)` then flat `rates[]` each tagged app+channel.

**BACKEND answer (user asked "all combinations or one?"):** [CODE] `_wt-commerce-main/.../Domain/Entities/Contracts/Contract.cs` — one `TariffPlan` per contract with a flat `List<ContractRate> Rates`, each row self-keyed by `ApplicationId`+`ChannelId` (dedup 5-tuple `App|Channel|Priority|Destination|Unit`, Contract.cs:295). Create/Update REPLACE the whole TariffPlan wholesale. So backend takes ALL combinations; it does NOT collapse to one. Risk: a buggy client sending fewer combos silently deletes rate rows (Update = full overwrite) — defense-in-depth: warn when saving fewer combos than stored.

**Grain divergence FLAG:** React SoT (`Source_of_truth_theme/latest/admin/contracts-{details,wizard,data}.jsx`) keys the matrix by **CommChannel ONLY** (Application = sibling scalar). Our Angular impl + the backend + the USER's stated intent all key by **(Application × CommChannel)** — our impl is MORE correct than the mock. Proceed per-(app,channel).

**PRIMARY FIX (surgical, preserves the typing-focus invariant):** include the selected combo in the structure key — `return \`${m.applicationId}::${m.channelId}::${priorities}::${destinations}\``. A combo switch → new key → `matrixRows`/`mountKick` recompute & re-project with the new values; a value-only `onCellChange` leaves app/channel/priorities/destinations unchanged → key unchanged → focused input not re-parented. Apply to BOTH admin + mgmt copies (mgmt view-only also goes stale). Add regression test: fill A → switch to same-shape B → assert display shows B(empty) → back to A → A restored → save → payload has BOTH combos.

**SECONDARY hardening (needs runtime evidence before changing):** (1) `createRateMatrixForSelection`/`syncRateMatrixIntoRates` compare `applicationId`/`channelId` with raw `===` (only priority/destination use `normalizeCatalogKey`) — if backend GET echoes ids in a different case/format than the `commerce/Node/{id}/applications` + `/comm-channels/visible` option `value`s, the EDIT round-trip filter returns ZERO → grid rebuilds empty / mis-merges. (2) `syncRateMatrixIntoRates` early-returns unchanged when `ratingUnit` is '' (if `resolveRatingUnitForChannel` fails for a channel → that combo's edits silently dropped on save).

**Why it shipped:** no test drives the full per-combination round-trip; the closest "structural change" test only shrinks the destination set (3→1 cell), which DOES change the key — it never tests a same-shape app/channel switch. Related [[reference_fe_structure_standard_angular21_2026_06_02]].

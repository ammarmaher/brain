**Two root facts drove the serious bugs:** (1) app is **zoneless** (`provideZonelessChangeDetection()` [CODE] app.config.ts:92) → a plain prop mutated in an async `subscribe()` does NOT trigger CD unless a signal updates or `markForCheck()` runs; (2) **HashLocationStrategy** (app.config.ts:100) → the Angular route is in `location.hash`, NOT `pathname`.

**FOLLOW-UP FIX (2026-06-08, same session — user-reported live bug):** forgot-password **OTP step** stuck on the "Verifying" skeleton after entering the OTP; never advanced to the create-new-password (Reset) screen. Screenshot showed `verify-otp` → `isSuccessful:true, stage:6` (PasswordResetPending) but no transition. ROOT CAUSE = the SAME zoneless-CD class I'd fixed in enter-otp but MISSED here: `git show origin/main:.../app.config.ts` = `provideZoneChangeDetection` (zone.js auto-ticked → main's plain-prop forgot-password worked 100% with ZERO markForCheck); current branch is `provideZonelessChangeDetection`, and `onVerifyOtp` success sets `otpScreenState=Success` → `stopTimer$.next()` (kills the only per-tick markForCheck) → `setTimeout(currentStep=ResetPassword)` — all plain-prop writes in async callbacks with NO signal write/markForCheck → froze on the last rendered state (Verifying skeleton). Form→Otp survived only because `isSubmitting.set(false)` (a signal) incidentally scheduled a tick. FIX = mirror enter-otp B4/B5 in `forgot-password-flow.component.ts`: `pendingTimers`+`later()` helper, `cdr.markForCheck()` after every async plain-prop transition (onVerifyOtp success + resetOtpForRetry + onResendOtp catchError/subscribe + onSubmitRequest Form→Otp), tracked setTimeouts cleared in ngOnDestroy. `nx build host-shell` GREEN. LESSON REINFORCED: a component is only zoneless-safe if EVERY async state path is signal-driven OR markForCheck'd — a recurring timer that you later STOP is not a safe CD source for the post-stop transition. Live retest user-gated (stack at localhost:4200).

**PLATFORM-WIDE PARITY AUDIT (2026-06-08, same session — user: "align ALL components with main"):** ROOT CAUSE class = the zone->zoneless migration. CONFIRMED: ALL THREE apps flipped `provideZoneChangeDetection` (main) -> `provideZonelessChangeDetection` (polishing-v0.4) — host-shell app.config.ts:92, admin-console:42, mgmt-console. So the regression risk = every component mutating PLAIN (non-signal) template-bound fields inside async callbacks (subscribe/setTimeout/finalize/.then) WITHOUT markForCheck. Audited all 3 apps via 3 parallel read-only agents (precise definition + false-positive exclusions: async-pipe / subscribe-only-navigates / writes-a-signal / non-template field). RESULTS: **host-shell = 1** real regression `layout.component.ts` — `buildNavItems()` sets plain `this.navItems` then `applyAccessToNavItems()` EARLY-RETURNS with no markForCheck when nav items carry no `access:` keys = the Falcon-ADMIN case -> admin sidebar fails to render after the async post-login `session$` emission (CLIENT users masked: their mgmt items have `access:` keys -> the await-path markForCheck at :409 fires). FIX = `this.cdr.markForCheck()` at end of `buildNavItems()` (cdr already injected). **admin-console = 1** `old-test-charging.component.ts` (default CD, plain fields, 5 callback sites) — but NOT in origin/main (branch-only dev/QA charging lab; live twin `testing-charging` is signal-based) so not a true main-parity item; FIXED anyway = inject ChangeDetectorRef + markForCheck in 4 `finalize` + `selectRun` next/error. **mgmt-console = 0** (fully signal-migrated: 53 components, 22 async, all write signals). Net: this CD class fixed in 5 components total (3 auth + layout + old-test-charging). Everything else (do-payment-priority-popup, organization-hierarchy-tree, service-pricing, topbar, sidebar, dashboard, all contracts/templates/wallet/org-hierarchy in admin+mgmt) was already signal-safe. host-shell + admin-console builds GREEN. KEY TAKEAWAY: when a Falcon app is flipped to zoneless, the ONLY at-risk components are the ones NOT yet migrated to signals — grep `\.subscribe\(|setTimeout` minus `signal(|markForCheck` per app to find them; most of the platform was already signal-migrated so the blast radius was small + bounded.

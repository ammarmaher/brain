Contact-group **share/edit/delete returned 403** with toast "Falcon users cannot share contact groups" for CLIENT users (e.g. accadmin) on PR 42603 branch (`feat/contact-group-validation-permissions-svc`, PolicyEnforcer present). It was NOT the gateway (FE correctly used core-gateway :7038 = client; system-gateway = :7256), NOT user-type, NOT the PES seed.

**Root cause:** `falcon-core-contact-group-svc` PolicyEnforcer POSTs `pes/authorize/resources`, but the contact-group service block in `C:\Falcon\Falcon\Falcon\docker-compose.yml` (~617-661) set `ServicesClients__Identity__BaseUrl` and **omitted `ServicesClients__Access__BaseUrl`**. With `ASPNETCORE_ENVIRONMENT=Development` it fell back to `appsettings.Development.json:47` `Access:BaseUrl=http://localhost:5296`. Inside the `falcon-contact-group-1` container `localhost:5296` is its OWN loopback, not `falcon-pes-1` → connection refused → `PolicyEnforcer.cs:71` catch → **fail-closed deny** → `ForbiddenToShareContactGroup` (403). Blast radius = the 3 PolicyEnforcer ops (share/edit/delete); view/list/create/download don't call PES and stayed 200.

**FIX:** added `ServicesClients__Access__BaseUrl: http://pes:5296` next to the Identity override [docker-compose.yml:647], then `docker compose -p falcon up -d --no-deps --force-recreate contact-group`. Other PES-calling services already had it (docker-compose.yml:570). Reference correct value: `http://pes:5296`. **STATUS (verified 2026-06-20 by claude):** the compose file lives in the **`Falcon` orchestration repo** (`.../Falcon/_git/Falcon`, NOT falcon-essentials — that dir only holds `seed/`), full path `C:\Falcon\Falcon\Falcon\docker-compose.yml`.

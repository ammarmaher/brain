**Org-hierarchy "CommChannels & Services" / "Apps & Services" visibility toggle returns HTTP 422 `CannotHideServiceWithTheCurrentStatus` when turning a service OFF (e.g. WhatsApp) — NOT a bug, it's a Commerce domain rule.**

ROOT CAUSE (backend, working as designed): `FalconServiceConfigurationBase.SetVisibility(bool)` at `[CODE] falcon-core-commerce-svc/src/Falcon.Commerce.Domain/Entities/Node/FalconService/FalconServiceConfigurationBase.Operations.cs:122` throws when `!newVisibility && Status is Active|Expired|Disabled`. Companion `CanHide()` (line 16) = `Visibility && Status is InActive`. Status enum (`Enums .cs:54`): None=0, InActive=1, Active=2, Expired=3, Disabled=4. So a service can be HIDDEN only while `InActive` (visible but never activated). Once it has been activated (Active/Expired/Disabled — all imply activation occurred) it can never be hidden (would orphan a live/past billing subscription). Error key `[ErrorHttpStatus(422)]` in `FalconKeys.cs:227`. Flow: FE PUT `comm-channels/visibility {Visibility:false}` → `ChangeAccountCommunicationChannelServiceVisibilityHandler.cs:103` → `SetVisibility(false)` → throws.

BACKEND ALREADY SHIPS the per-row `canHide` flag (`GetAccountCommunicationChannelsHandler.cs:70` / `GetAccountApplicationsHandler.cs:68` → DTO → system-gateway → FE), so the fix is FE-ONLY, no backend change.

FE HISTORY: origin/main disabled the switch via `[disabled]="row.visibility && !row.canHide"`. polishing-v0.4 (product decision 2026-05-24) made the switch ALWAYS enabled + relied on backend reject + toast; 2026-06-21 also dropped the `!checked && !row.canHide` early-return. Net effect = user can fire a guaranteed-to-fail hide and only sees the 422 toast after clicking.

FIX APPLIED 2026-06-22 (claude, FE-only, NOT committed; branch polishing-v0.4): reintroduced the gate on the consolidated shared table `libs/falcon/src/shared-features/service-pricing-table/service-pricing-table.component.html` (the ONE table for BOTH Apps&Services and CommChannels, both consoles): switch now `[disabled]="row.visible && !row.canHide"`, wrapped in a `<span [attr.title]=...>` (disabled control suppresses its own pointer events, so the tooltip must live on a non-disabled parent). New i18n key `hierarchy.services.cannotHideTooltip` in en.json + ar.json. Corrected the stale always-enabled comment in `service-pricing-table.component.ts:562`. Revealing a hidden row (`!row.visible`) stays enabled (making visible is always allowed). The Stencil `<falcon-switch-tw>` honors disabled (blocks `toggle()`/`handleInputChange`, greys out, native `disabled` input). `nx build admin-console` GREEN (28.7s, exit 0; only pre-existing unrelated NG8102 + bundle-budget warnings).

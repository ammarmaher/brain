**Org Hierarchy → Info panel → "edit account name": a trailing space was treated as a valid 2nd character, then Save failed.** FIXED 2026-06-07 (claude), branch polishing-v0.4, repo `C:/Falcon/Falcon/falcon-web-platform-ui`, NO commits.

**ROOT CAUSE** [CODE] `libs/falcon/src/shared-utils/lib/validations/falcon-validations.ts` `accountName()` (and `nodeName()`, kept 1:1 per BUG-08 2026-05-29): `required` uses `.trim()`, `ACCOUNT_NAME_CHARSET = /^[\p{L}\p{N} &'-]+$/u` **allows space**, and `min/maxLength` count **RAW** `v.length` (Wave E 2026-05-24 "space counts as a character"). There was **NO edge-whitespace check** — unlike `personName()` which already rejects edges via `if (v !== v.trim()) return { whitespace: true }`. So `"a "` (len 2) passed min-2 but trimmed to `"a"`. The wire-builder ALSO trims (`buildXxxWireRequest`, proven by [CODE] `apps/admin-console/tests/wire-builders.spec.ts:134` `'  Acme Corp  '`→`'Acme Corp'`) → it sent `"a"` to the backend → **backend rejected "a" as < min-2** = the "validation error on save" the user saw (FE looked fine at 2 chars; backend bounced the trimmed 1-char name).

**FIX** — added `if (v !== v.trim()) return { whitespace: true };` after the `required` check (BEFORE charset, so the edge-space message wins since space ∈ charset) in BOTH `accountName()` and `nodeName()`. Edge-rejection + raw-length counting coexist (personName does both). The `whitespace` key already maps to `hierarchy.validation.whitespace` ("No leading or trailing spaces" en / "لا يُسمح بمسافات في البداية أو النهاية" ar, [CODE] en.json:1528) and is in `LIVE_ERROR_KEYS` → shows live AND on blur AND gates Save (`isInfoFormValid` calls `accountNameValidator`). **Centralized → one change fixes ALL consumers.**

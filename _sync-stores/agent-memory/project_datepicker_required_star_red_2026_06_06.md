Contract **Start Date** + **Expiration Date** required `*` rendered GRAY not RED, in BOTH Add (wizard step 1) and Edit contract — FIXED 2026-06-06 (claude), repo `C:/Falcon/Falcon/falcon-web-platform-ui`, branch polishing-v0.4, **NO COMMITS**.

**Where:** [CODE] both date fields are `<falcon-angular-date-picker [required]="true" [label]="…">` — admin Add `contract-information-step.component.html:37,48`; admin Edit `contracts-edit-contract.component.html:147,159`. The required `*` is rendered by the **date-picker COMPONENT itself** (not extracted markup like the Value ﷼ label), so this is a LIBRARY bug, not a feature bug — it affects EVERY required date-picker platform-wide.

**ROOT CAUSE (durable, token-scope class — same family as [[project_contract_info_value_label_to_span_lint_2026_06_06]] LESSON 2):** [CODE] `falcon-date-picker-tw.tsx:326` (the live `-tw` path; wrapper `useTailwind=true`) rendered the marker via `falconInputRequiredMarkerClasses()` → [CODE] `input-tailwind-classes.ts:231-233` returns `ms-[length:var(--falcon-spacing-1)] text-[color:var(--falcon-input-required-color)]`. But [CODE] `--falcon-input-required-color` is declared ONLY inside `:where(falcon-input, falcon-input-tw, falcon-angular-input, .falcon-input, [data-falcon-input], falcon-password, …)` in `input.tokens.css:33-57`. The date-picker host (`falcon-date-picker` / `-tw` / `falcon-angular-date-picker`) is NOT in that scope → `var(--falcon-input-required-color)` resolved to nothing → the `*` inherited the gray label color. The Shadow path (`falcon-date-picker.tsx:196`) was ALSO wrong — it rendered ` *` with NO color class at all. There was NO `--falcon-date-picker-required-color` token. **The date-picker was the ONLY form control borrowing another component's required token** — dropdown/combobox/multi-select/checkbox/radio/switch/textarea/email-field/phone-field each declare their OWN `--falcon-<comp>-required-color` (grep `*.tokens.css`).

**FIX (convention-aligned, mirrors `dropdown` exactly — token + helper + Shadow `.falcon-<comp>-required` rule). 5 lib files, NO app-file change (library fix auto-covers admin+mgmt, Add+Edit+View):**
1. [CODE] `libs/falcon-ui-tokens/src/components/calendar.tokens.css` — added `--falcon-date-picker-required-color: var(--color-falcon-red-500, #dc2626)` to the date-picker `:where()` scope (section 12.b; fallback matches the date-picker's own error red).
2. [CODE] `libs/falcon-ui-core/src/tailwind/date-picker-tailwind-classes.ts` — added `falconDatePickerRequiredMarkerClasses()` → `ms-[length:var(--falcon-spacing-1)] text-[color:var(--falcon-date-picker-required-color)]` (same spacing as before = pixel-identical) + header selector-map line.
3. [CODE] `falcon-date-picker-tw.tsx` — use the new helper at line 326; **removed** the cross-component `import { falconInputRequiredMarkerClasses } from '../../tailwind/input-tailwind-classes'`.
4. [CODE] `falcon-date-picker.tsx` (Shadow) — `<span class="falcon-date-picker-required" aria-hidden="true"> *</span>`.
5. [CODE] `falcon-date-picker.css` (Shadow) — `.falcon-date-picker-required { margin-inline-start: var(--falcon-spacing-1); color: var(--falcon-date-picker-required-color); }` (mirrors `.falcon-dropdown-required`).

**Zero regression to input/password** — the shared `falconInputRequiredMarkerClasses()` + `input.tokens.css` scope are UNTOUCHED (still used by input-tw, password-tw, falcon-input.component.ts). Rejected the alternative of adding date-picker tags to the input `:where()` scope (the password precedent) — that would pollute the date-picker host with ~80 unused `--falcon-input-*` tokens to get one; per-component token is the correct platform convention.

**VERIFIED (code/build/test/CSS — live pixel pending login):** `nx build falcon-ui-core` EXIT 0 (44s; date-picker `.tsx`+helper compiled, new import clean); `nx run-many build admin-console,management-console --configuration=development` EXIT 0 (strictTemplates clean). **CSS-verified in BOTH bundles** (the decisive proof for a "not red" bug): token `--falcon-date-picker-required-color: var(--color-falcon-red-500, #dc2626)` declared in the date-picker scope + compiled utility `color: var(--falcon-date-picker-required-color)` present in `dist/apps/{admin,management,host-shell}-console/styles.css` (1 each) → `*` resolves to red `#dc2626`. ⚠️ note: Tailwind v4 emits `color: var(…)` WITH a space — grep `color:var` (no space) gives a false negative. Tests: **admin 745/745 (35 files)** incl. `contracts-add-wizard.component.spec.ts`(25)+`contracts-edit-contract.component.spec.ts`(15); **mgmt 581/581 (25 files)**. No date-picker lib spec exists; no spec asserts the marker class.

**OPTIONAL follow-up (not done, off critical path):** `nx build falcon-ui-tokens` regenerates `libs/falcon-studio/src/lib/registry/component-tokens.generated.ts` so the falcon-studio showcase lists the new token. Apps don't consume that registry, so the contract fix doesn't need it; left un-run to avoid a noisy unrelated regen diff.

**LESSON (reusable):** a first-class Falcon form component that renders a required `*` MUST declare its OWN `--falcon-<comp>-required-color` token (in its `*.tokens.css` scope) and render the marker with its OWN `falcon<Comp>RequiredMarkerClasses()` helper — NEVER borrow `falconInputRequiredMarkerClasses()` / `--falcon-input-required-color`, which only resolve inside the `<falcon-input>` `:where()` scope and silently fall back to the gray label color everywhere else. This was the date-picker; audit any other component that calls `falconInputRequiredMarkerClasses()` from outside the input/password family (currently none remain after this fix).

**Opaque navigation-token system — generic service + org-hierarchy application (2026-06-08, claude + ammar-web-platform-ui, FE-only, NO commits, branch polishing-v0.4).**

GOAL (user): keep editable business ids (nodeId/userId/customerId/bookingId…) OUT of the browser URL so a normal user can't hand-edit a route/query param and Enter to load a different record. **Explicitly NOT backend security** — backend authz remains the real gate (verified earlier: `GetUserByIdEndpoint` tenant-scopes client reads, cross-tenant blocked; within-tenant node/PES read-scope is a separate backend decision). This is anti-casual-tamper + keeps ids off the address bar only.

**PHASE 1 — generic `NavigationTokenService`** (`[CODE] libs/falcon/src/core/lib/services/navigation-token.service.ts`, `@Injectable({providedIn:'root'})`, exported via `@falcon` from `core/index.ts`). Feature-agnostic. API: `createToken<TState>(scope,state,opts?:{ttlMs?,persistence?:'cross-tab'|'tab'}):string` · `resolveToken<TState>(scope,token):TState|null` · `clearToken(scope,token)` · `cleanupExpiredTokens()`. Token = `crypto.randomUUID()` (RANDOM opaque — NOT base64-of-state, NOT a hash of ids → leaks nothing). **STORAGE = cross-tab by DEFAULT (2026-06-08 fix for "copy link → new tab → paste"):** `'cross-tab'`(default)→**localStorage** (origin-wide → a pasted `/h/{token}` link RESOLVES in a NEW tab + survives refresh); `'tab'`(opt-in)→sessionStorage (this-tab-only). `resolveToken`/`clearToken`/`cleanupExpiredTokens` span BOTH stores (`allStores()`, localStorage first) so a token is found regardless of which persistence wrote it; **service holds ZERO in-memory state** (every method reads/writes web-storage directly → a fresh instance = new tab resolves any token by construction). Key `falcon:navigation-state:{scope}:{token}`. `OpaqueNavigationEntry<TState>={token,scope,state,createdAt,expiresAt}`. Default TTL 12h (override per call). resolveToken returns null on missing/malformed(+clears)/expired(+clears)/wrong-scope. cleanupExpiredTokens sweeps `falcon:navigation-state:*` across both stores; called opportunistically in createToken. SSR/privacy-safe (degrades to null). **Spec 14/14 GREEN** (incl. CROSS-TAB `new NavigationTokenService().resolveToken(...)` + `persistence:'tab'`→sessionStorage). The committed `libs/falcon/vitest.config.ts` is INTENTIONALLY narrow (user-details/rules only, node-env) so it does NOT pick up this core spec — run it via a throwaway jsdom config mirroring `apps/admin-console/vite.config.mts` (`plugins:[angularTestPlugins(),nxViteTsPaths()]`, `include:['src/core/lib/services/navigation-token.service.spec.ts']`), OR rely on the admin integration which exercises the real service.

**PHASE 2 — applied to org-hierarchy, BOTH consoles** (`apps/{admin,management}-console/.../features/org-hierarchy-page/`). URLs `/#/admin-console/org-hierarchy-page?node={id}` + `…/user/{userId}?node={id}` → **`/#/{console}/h/{token}`** (mgmt was `organization-hierarchy` → `h`). The node-vs-user VIEW lives in the token state, NOT the URL path. Scope `'organization-hierarchy'`. `OrganizationHierarchyRouteState={app:'admin-console'|'management-console',view:'node'|'user',nodeId,userId?}` (in `route-state.ts` per console). Routes: `{path:'h',loadChildren}` → `[{ path:'', providers+shellAccessGuard+canDeactivate:[orgHierarchyPageCanDeactivate]+data, children:[ {path:'',canActivate:[orgHierarchyBootstrapGuard],children:[]}, {path:':navigationToken',loadComponent:menu} ]}]`. **Mechanisms:** (1) `orgHierarchyBootstrapGuard` — bare `/h` mints `{view:node,nodeId:''}` + returns a UrlTree redirect (parent-absolute via `route.parent.pathFromRoot`) to `/{console}/h/{token}` (no loop — the `:navigationToken` route has no bootstrap guard). (2) Menu reads `:navigationToken` reactively (paramMap) → `resolveToken`; INVALID/wrong-`app` → `replaceWithFreshToken` (fresh nodeId:'' token, replaceUrl, no crash); valid+concrete nodeId → `applyTreeSelection`; valid+nodeId:'' → `refineBootstrapToken` on `onTreeReady` (default node → refined token via replaceUrl; `suppressBootstrapRefine` guard; `'' → default` transition kills any cycle). (3) View renders INLINE: `@if(view()==='user'){ @for(id of [selectedUserId()];track id){ <app-user-details-page [userId] [includeDeleted]="false" (dirtyChange)="state.setUserInfoDirty($event)" (back)="onUserBack()"/> } } @else { <app-node-workspace (openUserDetails)="onOpenUserDetails($event)"/> }` — NO `<router-outlet>`/child route for the view. (4) FRESHNESS: user→node `@if` swap destroys+recreates `<app-node-workspace>` → ctor `reloadUsers()`; user-view keyed-recreate by userId. (5) `navigateToState(next)` = `createToken` + `router.navigate([token],{relativeTo:route.parent})` (`:navigationToken`'s parent `''` sits at `/{console}/h` → `[token]` → `/{console}/h/{token}`; verified by RouterTestingHarness). (6) **UNSAVED GATE moved from CanDeactivate to IN-HANDLER** (node↔user is a same-route param change → no CanDeactivate): `onNodeSelect`/`onOpenUserDetails`/`onActionInvoke` call `state.confirmDiscardIfDirty()` and navigate only on `leave===true`; `onUserBack` clears `setUserInfoDirty(false)` first (shared page already gated → no double popup); whole-page `orgHierarchyPageCanDeactivate` STAYS for sidebar/cross-feature leaves.

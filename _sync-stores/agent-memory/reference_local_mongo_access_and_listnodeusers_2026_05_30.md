Reusable recipe for debugging Identity user-list queries against the local Docker stack.

**Local Mongo access (the non-obvious part):**
- `falcon-mongo-1` on `localhost:27017`, replicaSet `rs0`. Root creds: user `root`, password `example`, `authSource=admin` (read from `falcon-identity-1` env `MongoDb__ConnectionString`, NOT from `MONGO_INITDB_ROOT_PASSWORD` which is stale).
- Host-side `mongosh "mongodb://root:example@localhost:27017/..."` FAILS auth (URI parsing). RELIABLE: `docker exec -i falcon-mongo-1 mongosh --quiet --norc -u root -p example --authenticationDatabase admin < script.js`. For `--eval` with async driver calls, wrap in `(async()=>{...})()` + `await`; for sync `.forEach()` cursor style, pipe via stdin.
- DBs: `FalconIdentityDb` (coll `Users`), `FalconCommerceDB` (coll `Nodes`, `Tenants` — the org hierarchy), `FalconProvisioningDB`, `FalconChargingDB`, `FalconContactGroupDb`, `PES`. Zitadel = Postgres `falcon-postgres-1` db `zitadel`, user `postgres` (trust auth inside container), orgs in `projections.orgs1`, users in `projections.users14`(+`_humans`).

**Port map gotcha:** `localhost:7256` = `falcon-system-gateway-1` (Falcon/admin-facing), forwards `/identity/*` to Identity. Identity direct = `:7777`. Core (client) gateway = `:7038`.

**GET /identity/user = ListNodeUsers** [CODE] falcon-core-identity-svc ListNodeUsersHandler.cs + UserAggregator.cs:
- Role enum (Enums.cs): `1 SystemAdministrator, 2 Product, 3 Operation` (Falcon) · `4 AccountOwner, 5 NodeAdmin, 6 NormalUser` (Client). `?Role=4&Role=5&Role=6` = all client roles.
- `userType` comes from JWT metadata `user-type` (base64): `1`=Falcon, `2`=Client. Falcon caller → requested `NodeId`/`TenantId` honored, sees all roles, `IncludeDeleted` honored. Client caller → `TenantId` forced from JWT; if NOT NodeAdmin the requested `NodeId` is IGNORED and replaced with caller's own node.
- `User.NodeId` is BSON `[BsonRepresentation(ObjectId)]` element `nodeId`; the filter is **EXACT match** `Eq(nodeId, ObjectId(req))` — NO subtree expansion. Subtree needs the separate `PathPrefix` param. `IgnoreNodeIdFilter=true` drops the node filter (whole tenant).
- So "no users returned" with a broad role filter = the node id has no directly-attached users (often a parent/root node whose users sit on child nodes), OR the tenant genuinely has no Identity users.

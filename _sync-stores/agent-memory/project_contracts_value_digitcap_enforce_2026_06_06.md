**User ask:** in Add/Edit contract, the value fields (Step-1 **Value**, **Contract Details matrix**, **Addons**) must cap the digits BEFORE the decimal — "allows more than N digits"; after-dot (4 decimals) already works; both consoles.

**Clarification (AskUserQuestion — the literal "max 4 digits before the dot" CONFLICTED with the documented xlsx SoT of matrix=6/addons=9/Value=9 from [[project_contracts_cost_reskin_2026_06_04]] item 7).** User chose: **Q1 = "Keep 6/9, just ENFORCE"** (do NOT reduce to 4 — the issue is enforcement, not the cap value), **Q2 = "Both apps incl. mgmt"**.

**ROOT CAUSE (durable):** the before-the-dot cap is enforced ONLY by the Stencil `falcon-input-number-tw` **`wouldExceedMax`** guard, which **fires ONLY when a numeric `[max]` is bound** (it parses the prospective value vs `[max]`; `maxFractionDigits` handles the after-dot separately, on blur via `format()`). The **admin Step-1 Value input (`contract-information-step.component.html`) bound NO `[max]`** → unlimited integer digits typeable, only a SOFT reactive `numberInRangeValidator` error surfaced afterward = the reported bug. Admin matrix/addons/rate-card ALREADY bind `[max]` (999999.9999 / 999999999.9999) so they DID enforce 6/9. **Lesson: a Falcon `<falcon-angular-input-number>` without `[max]` has NO hard typing cap — the validator alone does not block typing.**

**Changes (5 M + 1 new, all under contracts):** (1) admin `contract-information-step.component.html` → add `[max]="999999999"` to Value (THE live fix). (2) mgmt `contracts-addons-section.component.html` → `[max]="999999999.9999"` on both addon inputs (left maxFractionDigits=6). (3) mgmt `contracts-rate-card-section.component.html` → `[max]="999999.9999"`. (4) mgmt `contracts-contract-details-section.component.{ts,html}` → **migrated the matrix editable cell from string `<falcon-angular-grid-input>` → `<falcon-angular-input-number>`** (min 0, `[max]=999999.9999`, maxFractionDigits=6, `[ngModel]=cell.ratePerUnit`, `(valueChange)=onCellValueChange`; swapped import GridInput→InputNumber; replaced `onCellCommit`/`cellDisplayValue`/`parseRate` with `onCellValueChange`/`normalizeRate`, mirroring the admin twin which was migrated 2026-06-04 but mgmt had DRIFTED/un-migrated). **PRESERVED read-only `formatAmount(v,6)`** (mgmt's long-standing 6dp view) — user said "changes are just for before the dot", so after-dot display untouched (admin twin uses 4dp; deliberate mgmt deviation). **ROOT CAUSE of "not red" (durable LESSON):** `text-falcon-danger-700` is a **PHANTOM Tailwind class** — Falcon's theme (`libs/falcon-theme/src/falcon-tailwind-tokens.css`) has **NO `--color-falcon-danger-*` scale; the red scale is `--color-falcon-red-*`** (red-500 `#dc2626`, red-700 `#a1191d`). So `text-falcon-danger-700` generates **ZERO CSS** (build-verified: 0 `.text-falcon-danger-700` rules in `dist/apps/*/styles.css`) → the `*` inherited the surrounding gray. The canonical required-marker color = `--falcon-input-required-color` = `var(--color-falcon-red-500,#a1191d)` = `#dc2626`. **FIX:** replaced all **8** `text-falcon-danger-700` (only in the contracts feature, 4 files, both apps — priceUnit/priceValue/application/commChannel asterisks) → **`text-falcon-red-500`** (resolves globally, no DOM-scope dependency; CSS-verified `.text-falcon-red-500{color:var(--color-falcon-red-500)}` in both bundles). The star markup already existed gated on `editable()` (Add wizard step-2 + Edit tab 'rate' both pass `[editable]="true"`); it was just colorless.

**DECIMAL hard-block (NEW shared opt-in prop):** the integer cap is hard-blocked while typing by the existing `wouldExceedMax` guard (fires only when `[max]` bound), but the after-the-dot cap (`maxFractionDigits`) was **blur-rounding ONLY** — a user could TYPE more decimals. Added **`@Prop() blockExcessFractionDigits=false`** to `falcon-input-number-tw.tsx` (+`wouldExceedFractionDigits()` guard wired into keydown/beforeinput, +`clampPasteFraction()` truncate-not-reject on paste) + the Angular wrapper `@Input` + `[attr.block-excess-fraction-digits]`. **Default FALSE = zero platform regression** (mirrors the `groupWhileTyping` opt-in precedent); Angular can't intercept the Stencil-rendered inner `<input>` so the decimal typing-block MUST live in the Stencil component. Enabled `[blockExcessFractionDigits]="true"` on all contracts price inputs (rate-card, matrix, both addon cards, both apps). 5 new lib spec cases in `falcon-input-number-tw.spec.ts` (PASS). **Caps were ALREADY correct in admin** (rate/matrix `[max]=999999.9999`+4dec, addons `[max]=999999999.9999`+4dec) — so admin needed only the red star + the decimal-block prop; **mgmt** needed full parity (added max/min/group/block, 6dec→4dec) **+ re-migrated the matrix `<falcon-angular-grid-input>` (string, accepted letters) → `<falcon-angular-input-number>`** (onCellCommit/cellDisplayValue/parseRate → onCellValueChange/normalizeRate, formatAmount 6→4, fixed 3 stale grid-input comments).

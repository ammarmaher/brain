## Critical facts learned (reuse these)
- **`falcon-image-uploader` IS the React-SoT port of the old photo-uploader's CARD mode** (56px circle + edit/delete pins + label/sub-label + drag hint + "Upload Photo" button). `[CODE] libs/falcon-ui-core/src/components/falcon-image-uploader/falcon-image-uploader.tsx:1-7`.
- **It exposes the raw File** via `(fileAdd)` detail `FalconFileUploaderAddDetail { file, nativeFile }` → base64 is reproduced consumer-side (no component change, backend wire unchanged). `[CODE] file-uploader-shared/file-uploader.types.ts:56-59`.
- **`ingestFiles` ALWAYS adds the picked file even if invalid** (status:'error', errorCode:'size', + blob preview) and fires BOTH `falcon-add` AND `falcon-error`. `[CODE] file-uploader-shared/file-uploader.behavior.ts:63-90`. The built-in size message renders ONLY via `renderBanner`, which early-returns when `showBanner=false` (`render.tsx:268-269`). So suppressing `showBanner` HIDES the oversize indicator → oversize bug. Fix = guard `(fileAdd)` on `detail.file.status==='error'` (don't set photo + set a `photoOversize` signal) + render a consumer red line + make the `[ngModel]` preview computed return `[]` when oversize (clears the rejected thumbnail via the CVA writeValue path).
- **Water-fill settle + oversize (FINAL behavior, user-confirmed 2026-05-31):** `aggregateStatus` (`file-uploader.utils.ts:80-86`) forces BOTH `success` AND `error` files → progress 100; `queued`→0. The user WANTS the water to FILL the whole background at 100% on completion → settle the descriptor to **`status:'success', progress:100`** (NOT `'queued'` — an earlier pass used `queued` for a clean photo, but that read as "recedes to idle", which the user rejected). Oversize/invalid → store the rejected `detail.file` descriptor in a `photoError` signal + DON'T set photo (not accepted); the preview computed returns `[photoError()!]` FIRST → `is-error` + progress 100 → **full RED water = the "red error status"** + a consumer red "too large" line (message; `showBanner` stays false so no success banner). `maxSizeMB=1` (validateNativeFile `utils.ts:48-57` rejects `>maxSizeMB*1MB`).
- **Water WAVE MOTION fix (2026-05-31):** the `-tw` (Light-DOM) variant's waves were a STATIC line because `fuTwWaveClasses` (`tailwind/file-uploader-tailwind-classes.ts`) used `animate-[fuWave_var(--falcon-file-uploader-wave-speed,4s)_linear_infinite]` — the COMMA inside `var(--…,4s)` makes Tailwind v4 silently DROP the utility (documented limitation). Fix = comma-free literal durations `animate-[fuWave_4s_linear_infinite]` + `animate-[fuWave_6.4s_linear_infinite_reverse]` (keyframe `@keyframes fuWave` is already global in `falcon-ui-tokens/.../file-uploader.tokens.css:247`). Rebuild falcon-ui-core. Also restored waves on Templates' document/image uploaders (same bug). RULE: never put a `var(--x,fallback)` (comma) inside a Tailwind `animate-[...]`/arbitrary utility — use a literal or an inline style.
- **"0 B" size-display fix (2026-05-31, SHARED COMPONENT):** avatar/profile uploaders showed `photo · 0 B` because consumers seed the preview descriptor from a stored base64 data-URL with `size:0` (a data-URL has no numeric size). Fixed in the shared render so it reflects on BOTH image + document uploaders + every consumer: `file-uploader.utils.ts` added `dataUrlByteSize(src)` (= `floor(b64.length*3/4)-padding`, exact decoded file size) + `resolveDisplaySize(file)` (= `file.size>0 ? file.size : dataUrlByteSize(file.url ?? file.previewUrl)`); `file-uploader.render.tsx` `labelSubText` success branch + `renderFileList` now use `resolveDisplaySize(...)` instead of raw `.size`. Real-size descriptors unaffected (size>0 wins). The displayed NAME stays the consumer placeholder `'photo'` (data-URLs carry no filename — consumer-side, out of scope). Rebuild falcon-ui-core. RULE: when seeding a preview descriptor from a data-URL, the component now derives the size — but pass a real `name` if you want a real filename shown.
- **falcon-ui-core layering:** must NOT import libs/falcon (no TranslatePipe). The image-uploader takes RESOLVED strings; consumers pass `'key' | translate`. Sibling pattern = `falcon-image-uploader.component.ts` (CVA, input()/output(), DI-seed FALCON_UPLOADER_DEFAULTS, `definedTw` gate). The wrapper has NO public `[files]` input — seed the preview via `[ngModel]` (CVA writeValue).
- **Tailwind scanning:** host-shell + admin + management `tailwind.css` all `@source` `libs/falcon-ui-core/src/angular-wrapper` + `/components` → Angular-Tailwind markup there compiles in all 3 apps (no CSS file needed).

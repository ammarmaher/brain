**Org Hierarchy after login fired 3 IDENTICAL `GET identity/user?PageNumber=1&PageSize=10&NodeId=<id>` calls, 2 "(canceled)" — ROOT-CAUSED + FIXED best-practice (NO caching, NO useless call), both consoles** (2026-06-08, claude, FE-only, polishing-v0.4, NO commits — working tree only).

**Repo/branch:** `C:\Falcon\Falcon\falcon-web-platform-ui` (the ACTIVE web repo; `deprecated-falcon-web-platform-ui` is stale/main). Angular **21.2.9**, zoneless, signals. Apps: host-shell + admin-console + management-console all live here.

**Root cause (NOT caching — a reactive modeling defect):** the users-list load in `apps/{admin,management}-console/.../org-hierarchy-page/services/state/users-state.signals.ts` used a **6-source `combineLatest([toObservable(effectiveNodeId), toObservable(effectiveNodePath), toObservable(effectiveNodeTenantId), toObservable(usersPageNumber), toObservable(usersPageSize), toObservable(refreshTick)]) → switchMap(getUsers)`**. The three `effectiveNode*` are ALL `computed` off the SINGLE `selectedNode()` (`[CODE] tree-state.signals.ts:109,114,118`). One node selection writes `selectedTreeNode` once → all three recompute → each `toObservable` emits separately → `combineLatest` emits **3×** → `switchMap` aborts the prior in-flight XHR each time → 2 "(canceled)". Kicker: admin `getUsers` did `void path; void tenantId;` (`[CODE] services.ts:176`) so all 3 URLs were BYTE-IDENTICAL = pure waste. Post-login sequence: tree `GET commerce/Node` resolves → `onTreeReady`→`applyTree` sets default selection ONCE → 3-way fan-out → 3 calls. DevTools "initiator" shows `organization-hierarchy-tree.component` because the async stack roots at the tree wrapper's getTree subscribe → treeReady → applyTree → combineLatest. Secondary writer: `NodeWorkspaceComponent` ctor `reloadUsers()` on mount (bumps refreshTick) — on cold path lands while id=null so no extra HTTP; AND `effect(() => { effectiveNodeId(); usersPageNumber.set(1); })` page-reset = an effect-writes-a-request-key-signal → a SECOND emission/canceled call when switching node while on page≥2.

**Why distinctUntilChanged is WRONG here (user explicitly rejected caching):** it's value-suppression = a cache that can swallow a legit same-node reload (`reloadUsers` tick). The true fix removes the fan-out so duplicates never exist; no dedup needed.

**The best-practice fix (NO caching, NO debounce, NO distinctUntilChanged — one emission per real change):**
1. **Collapse to ONE glitch-free trigger** — `private readonly usersRequestKey = computed(() => ({ id, [path (mgmt only)], pageNumber, pageSize, tick }))` then `toObservable(usersRequestKey).pipe(switchMap(...))`. A `computed` recomputes EXACTLY ONCE per change (glitch-free), so 1 selection → 1 emission → 1 HTTP. switchMap still cancels a GENUINELY superseded node (click B before A returns) — the only desirable cancel.
2. **`usersPageNumber = linkedSignal({ source: () => tree.effectiveNodeId(), computation: () => 1 })`** — replaces the page-reset effect. Page is ALREADY 1 inside the same recompute the key reads → switching node mid-page = ONE call (page 1), never an intermediate {newNode, oldPage} canceled correction. (Angular guidance: don't write signals from effects.)
3. **Drop dead params from `getUsers`:** admin `getUsers(id, pageNumber, pageSize)` (admin scopes by EXACT NodeId, ignores path); mgmt `getUsers(id, path, pageNumber, pageSize)` — mgmt KEEPS path (it sets `IgnoreNodeIdFilter`+`PathPrefix` for subtree scoping at `[CODE] mgmt services.ts:186-190`), drops only dead tenantId.

**Files edited (6):** admin+mgmt `users-state.signals.ts` (linkedSignal + single computed + removed combineLatest/page-reset effect), admin+mgmt `services.ts` (getUsers signature), admin+mgmt `users-reload-on-mount.spec.ts` (rewrote to 3/4-arg + buildSlice(initial) harness + 3 NEW regression tests: COLD null→node=1 call, node-switch=1 call, node-switch-while-page-3=1 call page1 — each FAILS on old fan-out code; the OLD spec never caught the bug because it PRE-SET the node before construct so combineLatest emitted once).

**LEFTOVER (optional follow-up, flagged not done):** `effectiveNodeTenantId` now dead in both tree-state.signals.ts; `effectiveNodePath` dead in admin (live in mgmt). Zero-cost lazy computeds — harmless dead definitions, NOT useless calls; left to preserve admin/mgmt tree-state symmetry.

**Why:** freshness-after-mutation in this codebase is hand-rolled per page (every list reinvents `_refreshTick`); the org-hierarchy users pipe modeled one selection as 3 streams. **How to apply:** when N derived signals share ONE source, NEVER `combineLatest(toObservable each)` — collapse into ONE `toObservable(computed(key))`; use `linkedSignal` (not an effect) to reset dependent state on a source change; reach for `rxResource({request,loader})` as the modern end-state (verify experimental flag in v21).

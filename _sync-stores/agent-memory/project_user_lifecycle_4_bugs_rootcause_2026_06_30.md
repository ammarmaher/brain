Four user-management bugs reported 2026-06-30 (org-hierarchy / profile → users). All root-caused in `C:\Falcon\Falcon\falcon-core-identity-svc`; a separate fix session was spawned per bug. INVESTIGATION-VERIFIED via code (not yet runtime/fix-verified).

**Bug 1 — Pending PHONE edit doesn't resend credentials.** NOT a handler bug: reissue path is correct (`UpdateUserProfileHandler.cs:57-104` fires on `Status==Pending && (emailChanged||phoneChanged)`, resolves phone-only→`eDeliveryMethod.Sms`, publishes `UserCredentialsGeneratedDomainEvent Reason=ContactUpdated`; notification handler `UserCredentialsNotificationHandler.cs:36-41` routes SMS). DEFECT = DI/config: `ServiceCollectionExtensions.cs:354-363` binds `ISmsSender`→`NoOpSmsSender` (logs only, `NoOpSmsSender.cs:11-15`) because `appsettings.json:95-101` `Sms:Enabled=false` + empty creds (Dev has no Sms section). Email works only because `SmtpEmailSender` registered UNCONDITIONALLY (`:365`). FIX = enable+credential SMS for the env (no .cs change); delivery is fire-and-forget so a creds failure looks identical — verify a real SMS arrives.

**Bug 2 — Pending EMAIL edit → neither new nor old credentials log in.** GSD-005 HTML-encoding bug. `UserCredentialsNotificationHandler.cs:59` `WebUtility.HtmlEncode(password)` into HTML email body, but Zitadel stores RAW (`ZitadelPasswordService.cs:33-46`). Generator special set `PasswordPolicy.cs:14` includes `&` → any `&`-password emailed as `&amp;` ≠ stored → login rejected at the Zitadel session password check (`ZitadelOtpService.cs:88,110`) BEFORE OTP/first-login-change (`LoginProcess.cs:40-62`). Email-edit reissue also regenerates+resets the pwd, killing the old one → neither works. SMS branch (`:90-94`) uses raw pwd so phone unaffected. FIX = drop `&` from `PasswordPolicy.cs:14` (`!@#$%^*()_+-=`) → HtmlEncode is a no-op; covers create (`CreateUserProcess.cs:130`) + unlock + edit. Keep firstName/username encoded. Already-issued `&`-pwd users stay broken until reissued.

**Bug 3 — AO edits ACTIVE user email/phone → UnVerified, can't edit, can't verify "invalid code length".** Contact-change path and OTP-send path disagree on who issues the code. Profile update auto-verifies phone in Zitadel (`ZitadelUserService.cs:186-198` SetUserPhone THEN VerifyUserPhone → code consumed) and sets email unverified WITHOUT returnCode (`:174-175`), writes new value+IsVerified=false to Mongo (`UpdateUserProfileHandler.cs:91-92`). FE send then sees Mongo `isSame==true` (`RequestPhone/EmailVerificationHandler.cs:46-58`)→RESEND branch→Zitadel `/resend` has no pending code→empty→FE `otpCodeLength<=0`→toast `hierarchy.otp.zeroLength` (`otp-dialog.component.ts:242-291`; the "invalid code length" string is FE-only, NOT a 4-vs-6 mismatch — config is consistently 6). "Can't edit" lock is FE-only+correct (`user-profile-edit.rules.ts:131,135`; backend `UserEditPolicy.cs:43-55` only blocks Suspended/Locked/Deleted). FIX = for Active verify-before-save, DON'T pre-push contact to Zitadel / DON'T persist new value+flags in Mongo; let send path hit `isSame==false`→`SetUser…Async` (real returnCode)→confirm handler persists. Keep Pending branch as-is. Reconcile already-broken users.

**Bug 4 — AO deletes user → SA sees it Active.** Two parts: (a) deleted user APPEARING in SA list = BY DESIGN (FE sends `IncludeDeleted=true` for Falcon; `UserAggregator.cs:29-31`). (b) status shows Active = DEFECT: soft-delete only flips `isDeleted` (`ChangeUserStatusProcess.cs:68-71`→`MongoRepository.DeleteAsync :110-126`), never sets `Status=Deleted(5)`; read DTO maps only Status (`UserMapper.cs:52-69`, `UserInfoResponse.cs` has no IsDeleted), FE maps label from numeric status. System already has `effectiveStatus=IsDeleted?Deleted:Status` internally (`ChangeUserStatusProcess.cs:24`) but never persists/projects it. FIX = persist `Status=Deleted` on soft-delete + one-time Mongo backfill `set Status=5 where isDeleted=true` (alt: derive Status in `UserMapper` — auto-fixes historical, no backfill). Gateway is pure YARP pass-through. Enum: Pending1/Active2/Suspended3/Locked4/Deleted5.

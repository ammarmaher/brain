**Contracts & Cost Management (admin edit pane) "click a blank input → it vanishes" — ROOT-CAUSED 2026-06-07 (claude, diagnosis; fix already present but UNCOMMITTED in working tree).**

Repo `C:/Falcon/Falcon/falcon-web-platform-ui`, branch `polishing-v0.4`. The 3 editable tabs (Rate Card, Contract Details matrix, Addons) render each editable cell through `<falcon-angular-data-table>` **Strategy-E projection**: the Angular wrapper mounts each cell's control as an `EmbeddedViewRef` into Stencil `<falcon-table-tw>`'s light-DOM `<td data-cell-mount>`, registered under key `` `${rowId}::${field}::${kind}` `` where `rowId = row[dataKey]` ([CODE] `falcon-data-table.component.ts:963`). Stencil re-emits `falcon-cells-mounted` after EVERY render ([CODE] `falcon-table-tw.tsx:557→612`); the wrapper then re-parents views and GC-destroys any whose key vanished ([CODE] `:988`, `:1037`).

**PRIMARY root cause (confirmed, matches screenshot): Rate Card duplicate row identity.** Rate-card binds `dataKey="clientId"` ([CODE] `rate-card-step.component.html`). FE derived `clientId` straight from backend `unitConversionId`, but **Commerce returns the SAME `unitConversionId` for EVERY conversion** in a contract (observed WhatsApp + Voice both `UC-…962`). Two rows → ONE projection key → the single shared input can sit in only one `<td>`, gets re-parented into the LAST duplicate (Voice), so the FIRST row (WhatsApp) renders EMPTY; any re-render reshuffles it (= "input disappears on click"). `findRowById` first-match also shows one row's value twice + an edit patches BOTH. **FIX:** `createDefaultUnitConversions` now sets `clientId = \`${unitConversionId}-${normalizeCatalogKey(code)}\`` (code is unique per row, idempotent) — [CODE] `models/contracts-display.models.ts` ~L295. Regression lock `tests/contracts/contract-unit-conversion-clientid.spec.ts` (4 tests).

**Contract Details matrix empty cells are NOT this bug** — `dataKey="priority"` is unique; the matrix seeds a FULL grid with `ratePerUnit:null` ([CODE] `contracts-display.models.ts:348-356`) so blank cells are genuine null-rate inputs by design.

**Validation/directive angle:** validation does NOT remove inputs — `onCellBlur`/`invalidCells`/`cellState` only toggle a red `[state]`. BUT the COMMITTED matrix code baked the flag into row `[data]` (`matrixRows()` depended on `invalidCells`) so a blur produced a NEW `[data]` ref → full re-projection → focus-less re-parent flicker. Working tree migrated to **Approach B**: `matrixRows` no longer depends on `invalidCells`; `[state]="cellState(...)"` reads the signal directly and updates in place because the data-table now `appRef.attachView`es each cell view + `withFocusPreserved` wraps the re-parent ([CODE] `falcon-data-table.component.ts` uncommitted diff). The `*falconDataTableCell` directive + `contentChildren` lookup is sound.

**Why the user STILL sees it:** all fixes (unique clientId, data-table `attachView`+`detachView`+`withFocusPreserved`+`effectiveTotalRecords`, matrix Approach-B) are in the WORKING TREE but **UNCOMMITTED**, and `falcon-ui-core` is a **shared Module-Federation lib** → running bundle must be rebuilt (lib + host/remotes) + hard-refreshed.

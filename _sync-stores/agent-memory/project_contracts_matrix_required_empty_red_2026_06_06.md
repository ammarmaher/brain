The Add-Contract wizard **step 3 (Contract-Details) rate-matrix** input cells (`<falcon-angular-input-number>` per priority×destination, inside `<falcon-angular-data-table>`) now show the **required-empty RED state**: focus a cell, leave it EMPTY on blur → the Falcon input `state='error'` (red ring + border via `--falcon-input` error tokens); it clears on the blur after the cell is filled. 2026-06-06 (claude), branch polishing-v0.4, **NO commits**, ALL Falcon components (NO PrimeNG / native HTML / SCSS / `::ng-deep`).

**⚠️ THE LESSON (cost me 2 wrong approaches — this is the platform rule):** to show per-cell validation INSIDE a `<falcon-angular-data-table>`, the error flag MUST be **BAKED INTO THE ROW DATA** (`[data]`) and read as a **plain row property** in the projected cell — exactly like the Add-Client wizard CommChannels/Applications steps ([CODE] `apps/admin-console/.../add-client-wizard/client-comm-channels-step/client-comm-channels-step.component.ts` `touched` signal + `viewRows()` baking `priceTypeError`/`priceValueError`, read in the cell as `[state]="row.priceValueError ? 'error' : 'default'"`). **WHY:** the data-table is a Stencil "Strategy E projection orchestrator" ([CODE] `libs/falcon-ui-core/src/angular-wrapper/components/falcon-data-table/falcon-data-table.component.ts:935-1022`) — each projected cell is an `EmbeddedViewRef` created with `createEmbeddedView`, `detectChanges()`'d ONCE at mount, its DOM nodes moved into a Stencil `<td data-cell-mount>`. These views are **NOT attached to Angular's CD tree**; they re-run `detectChanges()` ONLY when `falcon-cells-mounted` re-fires, which happens ONLY when `[data]`/`[columns]` get a NEW reference (Stencil re-render). So a per-cell `[state]="someMethod()"` / signal read in the cell **NEVER re-evaluates** on a signal change → the red never appears. Baking the flag into the row + mutating the source signal → fresh `[data]` ref → table re-projects → `mountOrReuseView` reuse path `detectChanges()` re-reads the row props (`<td key={col.key}>` is keyed → reused → NO `replaceChildren` re-parent → focus preserved). This is also why the re-projection on blur is safe (no focus loss on tab-to-next-cell).

**❌ FAILED APPROACH 1 (build/test-green but DEAD at runtime):** `[state]="cellState(priority,destination)"` where `cellState` read a `touchedCells` signal + `matrix()`. Compiled + unit-tested fine (logic correct) but the red NEVER showed in the browser — the detached projected cell view never re-evaluated `cellState` when the signal changed. **Unit tests that call the method directly CANNOT catch this** (they bypass the data-table render model). **❌ FAILED APPROACH 2 (rejected by user before impl):** native `required` + CSS `:user-invalid` + a scoped rule. Rejected because the codebase has ZERO `::ng-deep` / `:has` / `:user-invalid` / SCSS-into-Stencil — using them VIOLATES "follow our structure" (Falcon components only).

**✅ THE FIX (Add-Client pattern):**
- `invalidCells = signal<ReadonlySet<string>>` keyed `priority::destination` = cells visited-and-left-empty.
- `matrixRows()` (the `[data]`) reads `invalidCells()` (tracked) + bakes `cellErrors: { [destination]: boolean }` onto each flattened row (`cellErrors[dest] = invalidCells.has(key)`). Matrix VALUES read `untracked` → a per-keystroke value edit does NOT recompute `matrixRows` (preserves the "cell disappears as you type" reference-stability invariant — `matrixStructureKey`/`mountKick`/`invalidCells` are the only deps).
- Cell template: `[state]="row.cellErrors?.[dest.destination] ? 'error' : 'default'"` + `(focusout)="onCellBlur(row.priority, dest.destination)"`.
- `onCellBlur`: ADD key to `invalidCells` if the cell is empty, REMOVE if it now holds a value (clears red after fill); else no-op (no needless re-projection). `(focusout)` chosen over native `blur` (bubbles from the inner `<input>` to the host). `0` is a value (not empty). Editable-guarded.
- `invalidCells.set(new Set())` reset in `changeRateSelection` (app/channel switch → rebuilt grid opens clean).
- RED only (no per-cell "Required *" text — 11 dynamic destination columns would be noisy; Add-Client shows text because it has only 2 editable cols). Offered to add text if wanted.

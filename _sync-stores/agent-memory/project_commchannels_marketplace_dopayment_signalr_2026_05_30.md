## The fix (user directive: "wire DoPayment to match main, but drive it from SignalR — NOT main's 2s poll")
KEY REUSABLE FACT: the host-shell **`<app-do-payment-priority-popup>`** (`@host-shell/shared/do-payment-priority-popup`, 623 lines) IS the canonical SignalR DoPayment orchestrator. Wave-4 replaced the 2s `SimplePollService` with `OrderStatusRealtimeService.onOrderFinalized` (SignalR push, hub `{gateway}/hubs/order-status` JoinOrder/LeaveOrder); only a ONE-SHOT bounded fallback GET remains (NOT a poll loop). It owns the order saga + InsufficientFunds / WalletNotConfigForTheNode / CommChannelPriorityOrderRequired(reorder→resubmit) dialogs. Contract: bind **`[trigger]` = {id, accountId, nodeId, target:'application'|'comm-channel'}**, listen `(succeeded)`/`(failed)` (both carry `id`). It's **mgmt-consumable** (path alias `@host-shell/shared/*` in tsconfig.base; precedent: mgmt `org-hierarchy-page-menu` imports `@host-shell/shared/service-pricing`, which already wires this popup — so mgmt ALREADY bundles popup+realtime+@microsoft/signalr; my direct import adds ZERO new runtime risk). `OrderStatusRealtimeService` self-resolves the gateway via `APP_DEFAULT_GATEWAY` (mgmt→Core).

**5 files changed (mgmt only; NO shared-lib, NO backend, NO poll):** (1) `comm-mkt-view.config.ts` — `canDoPaymentForStatus()` (Expired|InActive|Pending*); gave `CommMktActionDef` a `gate` discriminator (`{kind:'allowedActions',rowAction}` | `{kind:'status'}`); added **doPayment** to `COMM_MKT_ACTIONS` (status-gated, SoT order Disable→DoPayment→Enable); `commMktActionVisible()`; gate-aware `resolveCommMktActions()`. (2) `comm-mkt-card.component.ts` — re-added `btnTeal` + DoPayment card-icon `@case`; `btnClass()` routes doPayment→teal. (3) `comm-mkt-view.component.ts` — list kebab `visible` uses `commMktActionVisible`; `onRowAction` forwards `doPayment`. (4) `comms-hub.component.ts` + (5) `marketplace-applications.component.ts` — mount the popup, `onAction('doPayment')`→`setRowBusy`+`payTrigger.set({id,accountId:acc,nodeId:acc,target})` (comm-channel / application), `onPaySucceeded`→clear+silent reload, `onPayFailed`→clear. **DoPayment is STATUS-gated, NOT allowedActions-gated** — the mgmt/Client gateway path strips DoPayment from `availableActions` (BUG-DOPAYMENT), so gating on it would hide a real action; the do-payment POST + order saga enforce authority server-side.

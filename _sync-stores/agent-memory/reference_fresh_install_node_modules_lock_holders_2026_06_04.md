Deleting `node_modules` for a fresh install on `C:\Falcon\Falcon\falcon-web-platform-ui` (TWO Falcon segs) reliably hits **two file locks** that must be released first:

1. **EPERM on `node_modules\@tailwindcss\oxide-win32-x64-msvc\tailwindcss-oxide.win32-x64-msvc.node`** — held by **WebStorm's Tailwind CSS Language Server** (`C:\Program Files\JetBrains\WebStorm <ver>\plugins\tailwindcss\server\tailwindcss-language-server`, a `node.exe` child of WebStorm). The Tailwind v4 LSP loads the repo's `@tailwindcss/oxide` native addon → holds the `.node` handle. **Must Stop-Process this PID** to delete root node_modules. It is NOT the IDE itself and NOT user files; WebStorm auto-respawns it and it reconnects after `npm install`. ⚠️ This REFINES the older "keep WebStorm LSP" note ([[reference_504_admin_console_mf_duplicate_servers_2026_05_31]]): keeping it is fine for dev-server kills, but for a node_modules DELETE the WebStorm Tailwind LSP MUST be stopped.
2. **EBUSY on `.nx\workspace-data\*-v2.db`** — held by the repo's **nx daemon** (`node_modules\nx\dist\src\daemon\server\start.js`). Stop that PID (safe; `nx reset` does the same; auto-respawns). Note the nx-console **nxls** under WebStorm may respawn the daemon, so kill the daemon close to the delete.

Find exact holders authoritatively via the Windows **Restart Manager** (`rstrtmgr.dll` `RmStartSession`/`RmRegisterResources`/`RmGetList` P/Invoke) — don't guess from command lines. KEEP gitnexus MCP node procs and WebStorm's nxls.

**Three** node_modules exist in this repo: root `node_modules`, `libs\falcon-ui-core\node_modules` (the nested Stencil lib, ~490MB/6.2k files), and a stray `libs\falcon-ui-core\src\components\node_modules` (only a Module-Federation `.federation/entry.*.js`, no sibling package.json). Root ≈ 381MB/38k files.

**Repo's own canonical fresh recipe** (`package.json` scripts): `npm run fresh` = `npm run clean:all && npm install`. `clean:all` = `clean` (dist, tmp, coverage, libs/falcon-ui-core/{dist,loader,www}, .graceful-fs-boot.cjs, demos/angular-playground/dist, .vitepress/{cache,dist}) + `clean:cache` (.angular, .nx/cache, .nx/workspace-data) + `clean:logs` (*.log) + delete `node_modules` & `libs/falcon-ui-core/node_modules`. `clean:all` does NOT touch the stray src/components node_modules, `.stencil` (that's `doctor`), or `package-lock.json` (kept — pinned). To do "fresh minus install": run clean:all's deletions + the stray, **stop the 2 lock holders**, leave package-lock.json. The nested `libs/falcon-ui-core/node_modules` is NOT restored by root `npm install` — it's recreated on the next `nx build falcon-ui-core` via `ensure-install.cjs` (its sentinel `@stencil/core` + hash `.falcon-install-hash` live INSIDE that node_modules, so deleting it forces a clean reinstall).

Fastest delete on Windows = Node `fs.rmSync(p,{recursive:true,force:true,maxRetries:5,retryDelay:200})` (handles long paths + transient locks better than PS Remove-Item).

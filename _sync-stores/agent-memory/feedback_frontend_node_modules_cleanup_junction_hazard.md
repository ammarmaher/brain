When cleaning the Falcon frontend (`C:\Falcon\Falcon\falcon-web-platform-ui`) by deleting `node_modules`, **never use `robocopy /MIR` or a naive recursive delete without excluding junctions.**

`node_modules\@falcon\ui-core` is a **junction → `libs\falcon-ui-core`**, created by `libs/falcon-ui-core/ensure-node-modules-junction.cjs` (runs on install/build). `robocopy /MIR` follows that junction and **permanently purges the real library source** (no Recycle Bin).

**Why:** On 2026-05-28, cleaning node_modules with `robocopy <empty> node_modules /MIR` purged all 1531 tracked files of `libs/falcon-ui-core`. Recovered fully via `git restore libs/falcon-ui-core` — the frontend IS its own git repo (branch was `polishing-v0.4`), and `node_modules` is gitignored so it correctly stays gone. Uncommitted edits inside the junction target would NOT have been recoverable.

**How to apply:**
- Safe deletion methods: `robocopy <empty> node_modules /MIR /XJ` (exclude junctions), or delete junction links first via `[System.IO.Directory]::Delete($link,$false)` then `Remove-Item -Recurse`. Check reparse points first: `Get-ChildItem -Recurse -Force -Directory | ? { $_.Attributes -band [IO.FileAttributes]::ReparsePoint }`.
- Git is the safety net — confirm `git -C <root> ls-files -d` is 0 after, and that uncommitted work (modified files outside the deleted path) is untouched.
- Harness safety guard misparses `cmd /c rmdir /s /q` (reads `/s` as a protected path) — avoid it; use the methods above.

**WebStorm lock-holders (separate gotcha):** WebStorm spawns *node-based* language-server helpers whose `CommandLine` is the **JetBrains plugin path, not the project path**, so filtering node procs by `falcon-web-platform-ui` MISSES them. They hold open handles on node_modules files and block deletion:
- `...plugins\tailwindcss\server\tailwindcss-language-server` → loads `@tailwindcss/oxide-win32-x64-msvc/tailwindcss-oxide.*.node`
- `...jsLanguageServicesImpl\js-language-service.js` (+ child `typingsInstaller.js`) → loads `node_modules/typescript`
- `...plugins\nx-console\nxls\main.js` → reads the nx workspace

Find them by loaded module (`(Get-Process).Modules | ? FileName -like '*tailwindcss-oxide*'`) or kill by LS identity (`CommandLine -match 'tailwindcss-language-server'`). They **auto-respawn and are safe to kill**; the actual IDE is the separate Java process `webstorm64.exe` (do NOT kill it). The nx daemon (`node_modules\nx\dist\src\daemon\server\start.js`) also locks node_modules.

**Falcon frontend dev-server ports:** host-shell `:4200`, management-console `:4301`. See [[project_admin_to_mgmt_e2e_verified_2026_05_28]].

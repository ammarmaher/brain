How Falcon wallet integrates with the backend (3-agent deep-dive 2026-06-02). The integration target for wiring `new-wallet-balance` to APIs.

**THREE HTTP calls only** (SoT = `apps/{admin,management}-console/src/app/features/wallet-balance-management/services/wallet-balance.service.ts`):
1. **LOAD (the one call that loads everything):** `GET api/commerce/accounts/{accountId}/hierarchy?currency&balanceDistribution&walletStructure` → `ServiceOperationResult<IWalletDataResponse>`. It's a **gateway AGGREGATION** (FastEndpoint, not YARP) that fans out to Commerce(hierarchy) + Identity(users, only if UserBased, `WalletOwnerOnly=true`) + Charging(`POST /api/Wallet/get-account-wallets`, only if `!canSave`) and returns a pre-merged FE-shaped payload. Admin→**System GW :7256** (FalconOnly), mgmt→**Core GW :7038** (ClientOnly; gateway takes tenant from JWT, IGNORES the path id).
2. **SAVE strategy:** `POST commerce/setting/wallets` (`ISaveBalancesRequest{ownerId,currency,walletBalanceType,walletType}`) — admin only, **FalconOnly, set-once** (2nd call → `WalletSettingsAlreadyConfigured`). mgmt has the method but it's UNWIRED (view-only).
3. **TRANSFER:** admin `POST charging/wallet/transfer` (arg-less gateway) | mgmt `POST wallet/transfer` with **explicit `useGateway(Gateway.ChargingGateway)`** → backend `POST /api/Wallet/transfer`. Body `ITransferRequest{amount,currency,description?,source,destination}` where `source/destination = ITransferEndpoint{walletId?,channelId?}` → `ITransferResponse{success,message?,transactionId?}`.

**Gateway base = relative path + `useGateway()` HttpContext flag → `RuntimeBaseUrlInterceptor`** resolves base from `window.FalconRuntimeConfig.baseURL{System,Core,Charging,Identity}Gateway`. `Gateway` enum: Core=1,System=2,Charging=3,Identity=4. Admin `APP_DEFAULT_GATEWAY`=System, mgmt=Core (per-app app.config.ts).

**single vs multiple / node vs user = PARAMS → RESPONSE SHAPE, not separate endpoints:** `walletStructure`(1 Single/2 Multiple) + `balanceDistribution`(1 NodeBased/2 UserBased) + `currency`(1 SAR/2 Points) are **suggestion defaults only when not yet configured**; once configured the server values win (`summary.walletType/walletBalanceType`). Single → `node.balance` scalar + `summary.totalBalance`; Multiple → `node.channelBalances[]` + `summary.channelWallet[]` + `channels[]`. UserBased merges Identity users as `node` children with `nodeType=User(3)`; FE filters the SAME tree by `nodeType` (Organization=1/Service=2/User=3). `canSave=true` = "not yet configured" → gates the strategy Save/edit.

**DRAWER dropdowns are built CLIENT-SIDE from that ONE aggregation response — NO separate dropdown API.** Source/Dest = master(summary) + comm-channels(summary.channelWallet/channels) + nodes/users(node tree); per-channel Source/Dest Wallet from `entity.channelBalances[]` (dest wallet LOCKED to source channel). Pairing rules (matrix) are FE; backend re-validates. `node.id` = Charging wallet id if a wallet exists else commerce node/user id; `node.disabled=true` when owner has no wallet (don't send as transfer endpoint).

**DTOs to REUSE VERBATIM** (`models/wallet-balance.models.ts` + `transfer.models.ts`): IWalletQuery, IWalletDataResponse{accountInfo,channels[],summary,node,canSave}, IWalletSummary{masterWalletId,totalBalance,currency,channelWallet?,walletBalanceType,walletType}, IBalanceNode{id,parentId?,nodeType,name,expandable,balance?,channelBalances?,disabled?,children?,path?(mgmt)}, IWalletChannelBalance{balance,channelId,walletId}, IChannelBalance{channelId,walletId,balance,name}, IChannel{id,name,displayOrder}, IWalletAccountInfo, ISaveBalancesRequest, ITransferRequest/ITransferEndpoint/ITransferResponse, enums. These are FIELD-FOR-FIELD = gateway `AccountHierarchyResponse` / `TransferBalanceRequest` (gateway header comment: "names dictated by frontend"). Wire field `walletId` is lowercase `w` (`[JsonPropertyName("walletId")]`).

**Admin vs mgmt:** admin=multi-account via `<app-organization-hierarchy-tree mode="falcon-full">` picker (self-fetches commerce/Node + PES) + Master Wallet card + strategy Edit/Save + 4 PES keys (adminConsole.{masterWallet.view, walletStrategy.view, walletStrategy.edit, wallet.transfer}). mgmt=single-tenant from session(tenantId||client_id), NO tree, NO master card, view-only strategy, 1 PES (managementConsole.wallet.transfer); per-pair directional PES ported but DISABLED (`PER_PAIR_PES_ENABLED=false`). Services are classic Injectable+HttpClient/HttpService returning Observables (no signals/httpResource); state lives in components. Transfer NOT idempotent (disable Submit in-flight); errors → branch on HTTP status, show `errorMessages[0]`.

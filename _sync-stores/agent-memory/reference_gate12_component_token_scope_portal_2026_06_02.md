[CODE] `tools/gates/gate-12-component-token-scope.mjs` enforces that EVERY `libs/falcon-ui-tokens/src/components/*.tokens.css` declares its `--falcon-<name>-*` vars under a `:where(falcon-<name>, …)` selector, NOT `:root` (≈3,500 component vars on `:root` inherit to every element → freezes Chrome DevTools on inspect). Regex gate: fails if any line matches `^[ \t]*:root\s*\{`, OR if no line matches `^[ \t]*:where\(\s*falcon-`. So the first selector inside `:where(` must literally start `falcon-` (multi-line `:where(\n  falcon-…` is fine; `\s*` eats the newline). Compliant template (`input.tokens.css:33`, radio, wallet): `:where(falcon-X, falcon-X-tw, falcon-angular-X, .falcon-X, [data-falcon-X])`. `:where()`=specificity 0,0,0 (LOWER than `:root` 0,1,0) → app/host overrides still win, never harder.

**Non-obvious coupling (the trap):** the 4 portaled-popover components — **calendar (+date-picker), dropdown, multi-select, phone-field** — had been DELIBERATELY promoted to `:root` (wave portal-popovers 2026-05-15) because [CODE] `libs/falcon-ui-core/src/utils/popover-portal.ts` `portalToOverlay()`/`ensurePortaled()` physically RE-PARENTS the popover panel via `container.appendChild(popover)` into `.falcon-overlay-container` (a `<div>` appended to `<body>`). Once moved, the panel is a light-DOM child of `.falcon-overlay-container` and inherits custom props from THERE, not from the `<falcon-*>` host. Still live at runtime (Stencil shadow cores call it in `componentDidRender`; Angular wrapper adds Top-Layer promotion ON TOP but the DOM relocation still happens). ⇒ Their `:where()` MUST include `.falcon-overlay-container` (panel) AND the component tags (inline trigger) or the portaled panel renders UNSTYLED. Putting ~350 panel/option tokens on `.falcon-overlay-container` is fine (10× under the 3,500 freeze threshold; container is usually empty).

**2 fallback-less cross-consumers:** (1) `overlay.tokens.css` `--falcon-overlay-z-index` (=100000) is read WITHOUT fallback by `organization-hierarchy.tokens.css:182` (`--falcon-org-hierarchy-ctx-menu-z-index: var(--falcon-overlay-z-index)`, inside org-hierarchy's OWN `:where`), consumed by the INLINE (non-portaled, NOT Top-Layer, so z-index genuinely matters) ctx-menu at `falcon-organization-hierarchy-tree-tw.tsx:1131` → overlay's scope must also list the org-hierarchy host selectors. (2) `overlay-layer.tokens.css` backdrop tokens are read only by in-file `dialog::backdrop` (matching `var(…,fallback)`) → scope includes `dialog` (`::backdrop` inherits from its dialog) so the default stays tunable; visually identical via fallback otherwise.

Density refs (`var(--falcon-density-input-height-md, 40px)`) + `--falcon-input-icon-color` cross-refs resolve identically before/after (density is global on `:root,[data-density='comfortable']`; the icon-color refs were already inert at `:root` since input.tokens.css is scoped). **2026-06-02 (claude):** rescoped all 6 offenders (calendar/dropdown/multi-select/phone-field/overlay/overlay-layer) — gate-12 exit 0 (55 files OK), `nx build host-shell+admin-console+management-console` all green (--skip-nx-cache).

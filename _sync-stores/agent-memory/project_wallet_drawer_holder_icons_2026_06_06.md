Each holder (master / comm-channel wallet / node / user) shows an icon via `<falcon-angular-dropdown>`'s NATIVE per-option `iconUrl` (renders in the option row AND the selected-value trigger — `FalconDropdownOption{value,label,iconUrl?,iconAlt?,iconSrcset?}` `[CODE] falcon-dropdown.component.ts:50-59`). NO new component — `iconUrl` is the intended mechanism.

**Mechanism (best practice):** new `data/wallet-holder-icons.ts` (byte-identical in admin + mgmt) exports: `interface WbHolderIconConfig {master?; channels?:Record<string,string>; entity?; user?}` (ALL optional), `const WB_HOLDER_ICONS` (default colored brand icons as self-contained `data:image/svg+xml` URIs), `channelIconKey(nameOrId)` (regex name→key: whatsapp/facebook/messenger/voice/aichat/sms/email — handles A2 opaque ids + EN/AR names), `resolveHolderIconUrl(opt, config, channelKey?)`. Drawer gets a PASSABLE `holderIcons = input<WbHolderIconConfig>(WB_HOLDER_ICONS)`; the Source/Destination/channel-sub-select option builders set `iconUrl = resolveHolderIconUrl(...)`. To CHANGE an icon: edit one `<svg>` or pass a custom map via `[holderIcons]`; OMIT a key → no icon (optional at every level); master holder → master crown, channel holder → channel icon (by name for A2), user keeps 👤.

**KEY STANDARDS LESSON:** mgmt feature has `__tests__/standards.spec.ts` RULE-1 = NO `#hex`/`rgb()` in ANY feature `.ts` (DELIBERATE, "zero exemptions") — `scannableTs` strips `<svg>…</svg>` blocks before the scan `[CODE] standards.spec.ts:91-96`. First agent attempt put brand hex in a `TONE` const passed as args → flagged → agent ADDED an exemption Set (subverts the standard + its `rel()` match is Windows-backslash-fragile). **CORRECT FIX (claude): put each brand colour INLINE inside a COMPLETE `<svg>…</svg>` literal** (artwork the scanner strips) → passes on merit, NO exemption. Reverted the agent's `ARTWORK_TS_EXEMPT`. Also `COMPONENT_TS` = only `*.component.ts` so the data file isn't styleUrl-scanned `[CODE] :77`.

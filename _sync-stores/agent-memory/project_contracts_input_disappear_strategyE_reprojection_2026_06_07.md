**"Click a contract matrix input → it disappears / loses focus" — ROOT-CAUSED + FIXED via ULTRACODE (2026-06-07, claude). Build+test GREEN; live runtime pending (auth-gated). NO COMMITS.**

**ROOT CAUSE (code-traced + adversary-confirmed):** editable contract cells in `<falcon-angular-data-table>` (Rate Card + Contract Details matrix tabs, ADMIN add/edit only — mgmt is read-only) are injected via **"Strategy E"**: Stencil `[CODE] falcon-table-tw.tsx:557/612` emits `falcon-cells-mounted` every render → wrapper `[CODE] falcon-data-table.component.ts` `mountOrReuseView` does `m.element.replaceChildren(...rootNodes)` re-parenting the focused `<input>` → focus/caret lost = "disappears". App is **zoneless** so only a SIGNAL change re-projects. The TRIGGER: matrix `onCellBlur`→`invalidCells` signal, and `matrixRows()` (the `[data]` source) READ `invalidCells` + baked `cellErrors` → blur minted a fresh `[data]` array → re-projection. **Deeper cause:** projected cell `EmbeddedViewRef`s were created with `tpl.createEmbeddedView()` but NEVER `appRef.attachView()` → orphaned from the CD tree → a signal read inside a cell never refreshed → that's WHY the team had to bake validation into `[data]` (forcing re-projection). Intermittency = the re-projection only fires on an invalidCells STATE TRANSITION + only yanks focus when Stencil RECREATES the `<td>` + async microtask race.

**FIX (best-practice, root-cause, NOT a focus hack — 7 files, 150/97):**
1. **Orchestrator `falcon-data-table.component.ts` (SHARED):** `this.appRef.attachView(view)` on cell first-mount (mountOrReuseView ~1014) → projected cell views join zoneless CD → a signal read in the cell updates IN PLACE with no `[data]` churn. Matching `this.appRef.detachView(view)` before `view.destroy()` on BOTH teardown paths (ngOnDestroy 645, orphan-GC loop 969). New `withFocusPreserved(host, fn)` wraps ONLY the reuse-path `replaceChildren` (defense-in-depth: capture activeElement+selectionStart/End/Direction, restore after; strict no-op when unfocused). Reuse-path `detectChanges()` KEPT (non-signal consumers). **Shadow-row path (`mountOrReuseShadowView`/`shadowViewRegistry`) UNTOUCHED** (never attached → never detached).
2. **Matrix `contract-details-step.component.ts` (admin) + `contracts-contract-details-section.component.ts` (mgmt twin, byte-parity):** `matrixRows()` drops the `invalidCells`/`cellErrors` baking → depends ONLY on `matrixStructureKey`+`mountKick` (shape-level) so `[data]` changes ONLY on real structural change (app/channel switch). New `protected cellState(priority,destination)` reads `invalidCells()`+`cellKey()`. `.html` `[state]` changed `row.cellErrors?.[dest]` → `cellState(row.priority, dest.destination)`.
3. Both specs retargeted (`errorOf` reads `cellState` not `matrixRows().cellErrors`) + 2 new invariant tests each (matrixRows ref STABLE on blur; rows carry no `cellErrors`). Stale doc-comments on `invalidCells`/`onCellBlur` corrected.

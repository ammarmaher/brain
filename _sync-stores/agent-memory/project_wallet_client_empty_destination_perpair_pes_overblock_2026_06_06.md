**BUG (user, Mitsubishi client):** management-console (Client view) Balance-Transfer drawer Destination dropdown shows EMPTY when it should list the client's other nodes/users.

**ROOT CAUSE (code-confirmed 2026-06-06, claude):** the **W4 per-pair directional PES pre-filter** over-blocks the Destination list. Chain: the dropdown is fed `accessibleDestOptions = applyAccessFilterToDestinations(destOptions, srcOpt, q => access.can(q))` (`wbm-balance-transfer-drawer.component.ts`); for a Client **entity→entity** pair the filter KEEPS a destination only if `can(FalconAccess.managementConsole.wallet.transferOwnerOwner({sourcePath,destinationPath}))` is true (`access-filter.ts:65-69,111`); `AccessControlFacade.can()` = `store.can()` which is **unknown→deny by default** (`access-control.facade.ts:56`) and the drawer's own ensure-priming comment admitted **fail-CLOSED on a resolvable directional query**. So when the live PES does NOT grant `transfer-owner-owner` for the client role (the directional actions were NEVER live-verified — the registry's "verified live" claim was stale/wrong) OR the `ensure()` priming doesn't land → ALL entity destinations are stripped → EMPTY. This is exactly the W4 risk flagged at build time ("runtime PES round-trip not exercised in-browser").

**FIX (FE-only, mgmt drawer):** REMOVED the per-pair PES pre-filter from the drawer — `destFalconOptions` + the keep-destination-valid effect + `noEligibleDestination` now read the raw `destOptions` (the pairing matrix); removed `accessibleDestOptions`, the `ensure(collectPairAccessQueries())` priming effect, the `isSelectedPairAllowed` clause from `canSave`, the `AccessControlFacade` injection + the access-filter import. The Destination now offers the full pairing-matrix list; the **coarse `wallet.transfer` gate (W2) + the backend re-validating every transfer POST are the real authority**. KEPT `access-filter.ts` + its spec as a PARKED pure module (re-wire only once the backend reliably provisions transfer-<pair> AND it's live-verified). Updated `pes-gating.spec.ts` W4 block → asserts the drawer NO LONGER wires the filter + reads destOptions.

**VERIFIED (as far as the env allowed):** drawer clean (0 dangling per-pair refs); `pes-gating.spec` 17/17 GREEN (text-based, runs despite env); 0 test failures (268 passed); HEAD 719d1b15 unchanged, NO commits, 0 backend (.cs). **⚠️ FULL vitest suite + LIVE test BLOCKED by EXTERNAL/concurrent issues — NOT this change:** a concurrent session is mid-editing `libs/falcon-ui-core` (falcon-data-table / falcon-input-number / falcon-table-tw / components.d.ts uncommitted) which breaks `@falcon/ui-core/angular` resolution APP-WIDE (16 files fail to COLLECT — contracts/contact-groups/libs, not wallet), AND the dev server (nx serve) was STOPPED by that work (no browser connected → can't live-test, can't log in per credential policy).

**Q (user 2026-06-07): 'admin user has no wallet' — bug or intended?** + verify transfer source/dest + what user sees in node/user view. (SAR->Points work discarded by user.) 3 parallel READ-ONLY agents, NO edits.

**WALLET-OWNERSHIP RULE (code-as-running, not just PRD):** live provisioning is decided ONLY by `eWalletBalanceType` — `[CODE] ResolveOwnerWalletProvisioningPolicy.cs:26-31`: `(UserBased,User)=>true, (NodeBased,Node)=>true, else false`. NodeBased -> wallets per NODE (`NODE:{nodeId}:ch:cur` + master `ACCOUNT:{acct}:ALL`); NO user gets a personal wallet (incl. owner/admin) — admin balance = the node wallet it administers. UserBased -> a `USER:{id}` wallet for EVERY non-deleted user (owner + admin + normal alike). Display (`GetAccountWalletsHandler.cs:69-81`) groups by OwnerType+OwnerId, ZERO role awareness.

**VERDICT on 'admin has no wallet' — MODE-DEPENDENT:**
- **NodeBased (NM/NS) = CORRECT / intended.** Wallets are node-owned; no user (not even Owner) has a personal wallet; admin's balance is its node wallet. BR-AM-27 'Node Admins hold but do not consume'. NOT a bug.
- **UserBased (UM/US) = the admin SHOULD have a USER wallet -> a missing one is a BUG.** Live code + the 24-client seed both fund every user incl. admin (role-blind).

**3 REAL DEFECTS FOUND (the deep-dive payoff):**
1. 🔴 **DEAD per-user wallet top-up path** (likely root cause). Per-user wallets are bulk-created at wallet-CONFIG time from the then-current user list (`ConfigureWalletSettingsHandler.GetOwnersAsync`). A user created AFTER wallet config relies on `commerce.user-wallet-create.v1`, published ONLY by `ProvisionWalletOwnerHandler` (`ProvisionWalletOwnerHandler.cs:56-68`), triggered ONLY by a `WalletOwnerEnabled` Identity event that **NO service ever produces** (Identity emits only `UserRoleLinkSyncRequested`; `"WalletOwnerEnabled"` is consumed/tested but never produced — `WalletOwnerEnabledEventConsumer.cs:33` + `UserRoleLinkSyncRequestedAvroEvent.cs`). => ANY user (admin OR normal) added after wallet-strategy config gets NO `USER:` wallet. Role-independent. **This is the most likely cause of the reported symptom in UserBased.**
2. 🟠 **Admin-console FE `slice(0,3)` 3-user cap** — `[CODE] admin data/build-rows.ts:30` `(org.users||[]).slice(0,3)` silently drops the 4th+ user from the TABLE and the transfer holder lists. mgmt removed this exact cap (`mgmt data/build-rows.ts:31-32`). If the missing admin is the 4th+ user under its node, THIS is the FE cause.
3. 🟡 **`walletOwnerOnly=true` role filter is a NO-OP** — Commerce sends `&walletOwnerOnly=true` (`IdentityService.cs:47-48`) but Identity `ListTenantUsersRequest` has NO such param/binder and `UserAggregator.GetUsersByTenantAsync` never filters by role => in UserBased, ALL users (incl. admin AND Account Owner) get wallets, contradicting the PRD intent ('balance assigned to individual users'; doc hints `ExcludeRole e.g. AccountOwner`). PRODUCT DECISION: should admins/owners hold personal user wallets in UserBased, or was the filter meant to exclude them? The per-user `WalletOwner` bool gate (`CreateOwnerWalletHandler.cs:67-101`: false=skip, null/true=provision) is dormant scaffolding.

**HOW TO TELL bug vs intended for a live symptom:** check the account's `eWalletBalanceType`. NodeBased => intended (no user wallets). UserBased => check whether the admin's User doc existed BEFORE WalletSettings were configured; if created after => defect #1 (dead top-up), not a role rule. Also check admin isn't the 4th+ user (defect #2).

Guards CONFIRMED: source!=destination (universal tail filter + canSave + validateSourceDestination), channel-lock (cross-channel forbidden), amount>0 & <= source balance. Admin users CAN be source/dest (NO role exclusion).

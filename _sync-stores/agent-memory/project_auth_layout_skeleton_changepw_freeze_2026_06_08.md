**host-shell features/auth — froze input/button/back-link positions across all auth components** (2026-06-08, claude, FE-only, NO commits).

User ask: make inputs + primary button same size/height/alignment and **frozen at the same on-screen location** across every auth screen (login → forgot-password → restore/reset), with consistent inter-element spacing. Evidence = two inspect-element screenshots (Get Started + Forgot Password) showing uneven distances.

**Root cause:** the auth feature already defines a canonical **"phone-area skeleton"** in `login-layout.component.scss` (the `:host` token block + the "PHONE AREA" comment). The contract per routed page:
- host `flex flex-col justify-start items-stretch w-full h-full` (fills card body)
- `<form class="flex flex-1 flex-col gap-[var(--login-form-gap)] pt-12">` (flex-1 fills, fields top)
- footer `<div class="mt-auto flex flex-col gap-[var(--phone-area-footer-gap)]">` = primary button + **reserved** `<div class="h-[var(--phone-area-back-link-slot)] flex items-center">` back-link slot.
Tokens: `--login-form-gap:24px`, `--phone-area-footer-gap:16px`, `--phone-area-back-link-slot:28px`, `--login-input-height` = `--login-btn-height` = **52px** (inputs+button already same height by token).
`mt-auto` pins the button to the SAME Y on every page; the reserved slot keeps the back-link Y stable even on pages with no back link (Get Started's slot is empty `aria-hidden`).

**get-started, forgot-password-flow (Step1 Form + Step3 Reset) already follow it.** The lone offender was **change-password**: (1) missing the host flex binding, (2) form `flex flex-col` **without `flex-1`**, (3) button wrapped in fixed `mt-[var(--login-footer-mt)]` (120px) instead of `mt-auto`, (4) back-link **outside** the form, **centered** (`mt-4 flex justify-center`) instead of in the reserved left-aligned slot. Net: its inputs/button/back-link landed at a different place than every sibling.

**Fix (2 files, change-password only):** added `host: { class: 'flex flex-col justify-start items-stretch w-full h-full' }` to the decorator; rewrote the footer to the canonical `mt-auto` phone-area footer + reserved back-link slot (back-link now left-aligned, classes byte-identical to forgot-password's). `--login-footer-mt` (120/72/40px) is now **dead** (was its only consumer) — left defined, harmless. GATE: `nx build host-shell --skip-nx-cache` GREEN (hash `bca4688f5f3dcf48`, 14.2s).

**FOLLOW-UP (same session) — login-layout language dropdown chip FIXED + LIVE-VERIFIED.** User: footer language flag "not centered / not in the circle", dropdown rendered as a wide bordered box. ROOT CAUSE: the `.login-lang-select` `::ng-deep` overrides targeted **non-existent classes** (`.login-lang-select__control`, `.fp-select__icon`, `.fp-select__label`) — guesses that never matched, so the Falcon dropdown kept its default full-width bordered `<button role="combobox">`; only the loose `img[alt]` + `[class*="-label"]` happened to match (circled the flag, hid the label), giving "flag-circle jammed left in a big box". The REAL Light-DOM (falcon-dropdown-tw.tsx): `<falcon-dropdown-tw><div.flex.flex-col.w-full><div.relative.w-full><button role=combobox …w-full><span.flex-1.truncate><span.falcon-dropdown-value-inner><img.falcon-dropdown-value-icon w-5 h-auto><span.falcon-dropdown-value-label></span></span><span.{chevron}.absolute>`. FIX (login-layout.component.scss only): collapse the w-full wrapper/anchor + host to `width:auto`/`inline-flex`; trigger `button[role=combobox]` → borderless/transparent/content-width/`gap:6px`; value `> span:first-child` → `flex:0 0 auto; overflow:visible` (don't stretch / don't clip ring); `.falcon-dropdown-value-label` → `display:none`; flag `.falcon-dropdown-value-icon` → 24×24 `display:block` `rounded-full` `object-fit:cover` `object-position:center` + teal-700 ring; chevron `> span:last-child` → `position:static` (un-absolute, flow tight). LIVE-VERIFIED on the PUBLIC login page (no creds) at localhost:4200: computed styles button 52px/`border:0`/transparent, flag 24×24 circle centered (natural 20×15, object-position 50% 50%), label `display:none`, chevron `position:static`; dropdown still OPENS with both options ["English","العربية"] + 2 option icons; zoomed screenshot = clean teal-ringed flag circle + chevron. nx build host-shell GREEN (523c606f). LESSON: the Falcon dropdown trigger is `button[role="combobox"]` in LIGHT DOM with semantic classes `.falcon-dropdown-value-{icon,label,inner}` + an `absolute` chevron + `flex-1 truncate` value span — target THOSE, never `fp-select__*`/`__control` (those don't exist). Panel is body-portaled into `.falcon-overlay-container` (outside the component), so page-scoped descendant CSS can't reach it — style it via the dropdown's `[panelClass]` input + a GLOBAL bare `::ng-deep .<class>` rule (gated by that class so blast radius = this panel only).

**FOLLOW-UP #2 (same session) — language PANEL (open list) made icon-only + both-options-visible, LIVE-VERIFIED.** After the trigger collapsed to a ~52px chip, the portaled panel inherited `min-width:52px` so the option rows (`flag + "English"` ≈ 85px) overflowed the 43px listbox → `overflow-y:auto` computed `overflow-x:auto` → a HORIZONTAL SCROLLBAR appeared (user saw `◄ ● ►` and thought "not showing both / scrolling"). Both options WERE always rendered (vertical fit fine); the scrollbar was the only defect. FIX: added `panelClass="login-lang-panel"` on `<falcon-angular-dropdown>` (login-layout.html) + GLOBAL `::ng-deep .login-lang-panel` rules (login-layout.scss): `[role="listbox"]{overflow:visible!important;max-height:none!important}` (kills scrollbars — 2 rows always fit), `[role="option"]{justify-content:center!important}`, `.falcon-dropdown-option-label{display:none!important}` (removes English/العربية text → icon-only), `.falcon-dropdown-option-icon{24×24 block rounded-full object-cover object-center + teal-700 ring}` (circle parity w/ trigger). LIVE-VERIFIED (localhost:4200 login, no creds): panelClass applied, listbox `hScroll:false vScroll:false scrollW==clientW`, optionCount 2 both visible-in-viewport stacked (y 1058/1098), justify center×2, labels `display:none`, both flags 24px `border-radius:9999px`; zoomed screenshot = 2 centered teal-ringed flag circles (US+SA) stacked, no text, no scrollbar. nx build host-shell GREEN. LESSON: collapsing a Falcon dropdown TRIGGER to a chip shrinks the PANEL too (panel min-width tracks the anchor) → narrow panel + labels = phantom horizontal scrollbar; either widen the panel or go icon-only. Option DOM: `[role=option]` row = `<img.falcon-dropdown-option-icon> + <span.falcon-dropdown-option-label>`. ⚠️ note: live env had a persisted sysadmin session (reload bounced `#/`→Dashboard); `#/login` still renders the login page directly so the footer chip stays verifiable without logging out.

**FLAGGED (not fixed — needs design ref):** the two OTP screens differ from EACH OTHER — `enter-otp` timer `h/w-[120px]` + `mb-[90px]`, success `text-xl`; `forgot-password-flow` Step2 OTP timer `h/w-[88px]` no mb, success `text-2xl`.

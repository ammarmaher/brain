## The architectural shift

| Aspect | Before Wave 1 | After Wave 1 |
|---|---|---|
| Backdrop element | `<div class="fixed inset-0 ... z-[var(--falcon-dialog-z-index)]">` | Native `<dialog>` element |
| Z-index in cascade | `--falcon-dialog-z-index` token UNDEFINED → computed `z-index: auto` (the bug) | Top Layer (`:modal` matches) — z-index irrelevant |
| Host `:host` | `display: contents` (host disappeared from layout) | Default block (host is the `<dialog>` ancestor) |
| ESC handling | Custom `@HostListener('document:keydown.escape')` | Native `(cancel)` event with `preventDefault()` gate for `closeOnEsc=false` |
| Backdrop click | `(click)="onBackdropClick($event)"` on the `.fixed` wrapper | `(click)="onDialogClick($event)"` on `<dialog>` with target-equals-dialog check delegating to existing `onBackdropClick` |
| Focus management | None (33 page controls remained tab-reachable while modal "open") | Native browser focus trap — 0 external controls reachable (massive a11y upgrade) |
| Body inert | None | Native browser inert behind modal |
| Backdrop styling | Tailwind `bg-falcon-neutral-900/45 backdrop-blur-[2px]` on the `.fixed` div | `dialog::backdrop` pseudo-element with the same `rgba(13, 63, 68, 0.45)` + `backdrop-filter: blur(2px)` |

## Wave 0 baseline KEY DISCOVERY

The original `--falcon-dialog-z-index: 99999` declaration at [CODE] `libs/falcon-ui-tokens/src/components/dialog.tokens.css:164` lived inside a `:where(falcon-dialog, falcon-dialog-tw, falcon-angular-dialog, .falcon-dialog, [data-falcon-dialog])` selector — so the cascade defined the variable ONLY on those specific dialog elements + their descendants. The `<falcon-angular-sending-credentials-dialog>` element is NOT in that selector list and is NOT a descendant of any `<falcon-angular-dialog>`. Therefore `var(--falcon-dialog-z-index)` resolved to undefined, and `z-[var(--falcon-dialog-z-index)]` collapsed to `z-index: auto`. The "stacking context trap" was actually a NULL-token bug. The Top Layer migration sidesteps both classes of bug structurally.

## Rules emitted

- **Native `<dialog>` + `showModal()` is the canonical fix for any "fixed div trapped by ancestor stacking context" AND for "undefined z-index token" bug class in Falcon overlay surfaces.** No z-index needed; browser Top Layer paints above everything.
- **`viewChild<ElementRef<HTMLDialogElement>>('dlg')` (NOT `.required`) is the correct pattern when the element is gated by `@if (...)` — the ref returns `undefined` while the @if is false; guard via `if (!el || !el.isConnected) return;`.**
- **`afterNextRender()` MUST be wrapped in `runInInjectionContext(injector, () => afterNextRender(...))` when called from inside an `effect()` callback. The canonical pattern is: `private readonly injector = inject(Injector);` field init, then bridge from effect callbacks.** Without this, NG0203 fires at runtime even though the code type-checks and builds clean.
- **`@if (open()) { <dialog>...</dialog> }` is the right control-flow pattern** (not always-mounted with attribute toggle) when existing tests assert `querySelector('[role="dialog"]').toBeNull()` on closed state. Preserves test contract.
- **Preserve `role="dialog"` / `role="alertdialog"` attribute on the native `<dialog>` element** so existing `querySelector('[role="..."]')` selectors in tests + screen readers continue to match.
- **Backdrop styling via `dialog::backdrop` pseudo-element** with `rgba(...)` + `backdrop-filter: blur(...)` is the visual-parity path for any Falcon dialog migration from `.fixed inset-0 bg-... backdrop-blur-...`.
- **Native `showModal()` delivers a free focus trap** that closes a known a11y gap — Wave 1's baseline showed 33 external tab-reachable controls while modal "open"; Wave 1 result is 0. Future waves on other modals should expect (and prefer) this behavior over manual focus management.

**What it does:** hovering a node lights its full ancestor path. At each level: the **turn-in** (the node's own elbow, where the path lands at that level) = **`falcon-teal-700`**; the **descending level columns to its left** (the "rectangle" rails passing through deeper rows) = **`falcon-teal-400` (#698e92)**. Reading down a level's column: top (turn-in) row = teal-700, every row below = teal-400. Trail **stops at the hovered node** (siblings below + the node's own descendants stay dim). **Column 0 (the leftmost / top-level-client level) DOES light, within the hovered node's own client (`own[0]===hov[0]`)** so the first level shows; only OTHER clients' col-0 stays dim. ⚠️ TWO CORRECTIONS after live screenshots 2026-06-01: (a) col-0 was initially EXCLUDED → user reported "first level not lit" → now lights within-client; (b) descending was `teal-500` but **`falcon-teal-500`=#124c52 ≈ `falcon-teal-700`=#0d3f44 (both dark, two-tone invisible)** → switched descending to `falcon-teal-400`=#698e92 (genuinely lighter, distinct). User likely expected STANDARD-Tailwind teal-500 (bright #14b8a6); Falcon's teal-500 is dark.

**Architecture (key insight): ordered sibling-INDEX path, not an id Set.** `[CODE]` each row carries `data-index-path` (`ownIndexPath`=ancestorIndexPath+siblingIndex, threaded via new node @Inputs `siblingIndex`/`ancestorIndexPath`). `TreeHoverPathDirective` (directives.ts) reads the hovered row's `data-index-path` on mousemove → emits ordered `number[]` (`FalconTreeHoverPath` type changed Set→`readonly number[]` in models.ts; resets lastKey on mouseleave so re-entry re-emits). Panel stores `hoveredIndexPath` signal, passes down. Pure helper `computeTreeRailHighlight(ownIndexPath, hoveredIndexPath)` in **NEW** `falcon-tree-panel/utils/rail-highlight.ts` returns per-segment **tones** `RailTone='turn'|'line'|null`: `{ancestorRails: boolean[], elbow:{before,through,after}}`. Rules: ancestor-rail c lit('line'/500) iff `c>=1 && c<L && sameBranch(c) && own[c]<=hov[c]`; elbow when `depth<L && sameBranch(depth)`: `own[depth]==hov[depth]`→turn-in `{before:'turn',through:null,after:'turn'}`(700), `own[depth]<hov[depth]`→passing `{before:'line',through:'line',after:null}`(500); plus a **lexicographic `comparePaths(own,hov)>0` guard** = all-dim (covers later siblings AND descendants of the hovered node → "stop below"). Why id-Set failed: it lit only exact path rows (broken trail) AND had no ORDER, so couldn't express stop-below or sibling-above.

**`falcon-ui-core` build `FatalProcessOutOfMemory` + `EMFILE` (broke host-shell/admin/mgmt builds) — ROOT CAUSE = unbounded aggregate CSS-compile cost, FIXED 2026-06-04 (claude).** The CSS post-processing runs a FULL Tailwind v4 compile **once per shadow component** that `@import`s tailwind.css (**36** files): each = native `@tailwindcss/oxide` content scan of all **110** `.tsx` (`@source "../components/**/*.tsx"`) + full theme/utility AST in the worker V8 heap. Stencil runs `maxConcurrentWorkers` of these in parallel; `stencil.config.ts:29` had been raised `1→4` (2026-06-03 build-perf P3). **Measured ≈2–2.5 GB peak RSS per concurrent compile** (cold build @2 workers peaked ~5 GB build-RSS) → **4 workers ≈ 8–10 GB heap + 4× native FD burst** → on memory-/FD-constrained Linux CI (`Aborted (core dumped)`, default `ulimit -n` 1024) it blows the V8 heap (OOM) and the FD ceiling (EMFILE). **graceful-fs CANNOT help** — v4 moved scanning into the native Rust Oxide `.node` binary, whose file opens bypass Node `fs` (all graceful-fs patches). The prior "v4 removed EMFILE" claim was the false premise that let P3 raise the count. `build.cjs`'s `verifyNoStubsRemain()` then correctly refuses exit 0 (= the user-seen `BUILD FAILED … did not overwrite stub-seeded components` / `Refusing to exit 0`) — guard is the messenger, not the cause. **Why ALL apps: `falcon-ui-core` is the single shared web-components dep on every app's critical path (`dependsOn:["^build"]`, + falcon-studio) → one upstream failure = all downstream app builds fail.** `build.cjs` itself is fully SYNC (spawnSync + sync fs) — NO uncontrolled Promise.all; generators (web-types/vue-proxies/ensure-install) are sequential sync loops — NO leaked handles. **FIX (2 files only, byte-identical CSS output, NO commits, branch polishing-v0.4):** (1) `stencil.config.ts` `maxConcurrentWorkers: resolveMaxWorkers()` — derives workers from `freeMem ÷ ~2 GB/compile`, clamp by cores, floor 1 / ceiling 4, override `STENCIL_MAX_WORKERS`, logs decision (so concurrency = correct-for-host, NOT a magic number; scales UP to 4 when free RAM allows, DOWN to 1–2 when constrained); (2) `build.cjs` `invalidateIncrementalCache()` deletes `.stencil` on every FAILURE path (an OOM-killed worker leaves `.stencil` half-written; P1 keeps it across SUCCESS → without this a corrupt incremental state is reused) + `distIndexIsReal()` (size>0) replaces bare `existsSync(distIndex)` in the EMFILE-tolerance gate (seeder writes a 0-byte `dist/index.js` → `existsSync` was ALWAYS true → could exit 0 on early crash). **KEPT (do not weaken): `verifyNoStubsRemain` guard (strengthened, not removed), graceful-fs+`UV_THREADPOOL_SIZE`, Nx `cache:false`.** VERIFIED: nx build falcon-ui-core EXIT 0 + run-many host-shell/admin-console/management-console all EXIT 0 (bundles emitted 77/79/75 .js), 0 OOM/EMFILE/stub, 106 real defineCustomElement entries, adaptive proven (5.3 GB→2, 7.7 GB→3, 10.2 GB→4 workers). Report `C:\Falcon\plans\stencil-build-fix\SHARED-BUILD-ROOT-CAUSE-FIX-REPORT.md`. ⚠️ Verifying required STOPPING the live `nx serve host-shell` MF stack (run-executor+http-server+nx.js serve, ports 4200/4204/4301) — building APPS against a live MF serve corrupts static remotes; rebuilding the LIB is safe alongside a serve. Restart with `npm start`.

**SECOND CI FAILURE + FIX (2026-06-04, post-push of 0718c57a): per-process V8 HEAP-OOM, distinct from the aggregate-RAM OOM above.** Azure agent build (Linux, exit 134) died with `FATAL ERROR: Reached heap limit Allocation failed - JavaScript heap out of memory` at ~2096MB during Stencil's SOURCE-MAP OUTPUT phase ("generate custom elements + source maps" / "generate lazy + source maps"; stack = Builtin_JsonParse→SlowFlatten). ROOT CAUSE = Node's DEFAULT ~2GB old-space heap ceiling on the agent is below what source-map emission for 110 comps × 2 output targets needs — a SINGLE-process (main, output-gen) limit, so the worker-count strategy CANNOT help (it bounds concurrent compiles, not the main output process; the guard correctly DETECTED+STOPPED it but couldn't prevent it).

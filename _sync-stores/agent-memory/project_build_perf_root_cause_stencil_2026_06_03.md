(Original PLAN-phase note, superseded above:) The slowness is **one library on every app's critical path**: `falcon-ui-core` (Stencil web-components, repo `C:\Falcon\Falcon\falcon-web-platform-ui`). `nx build <app>` → `dependsOn ^build` → `falcon-ui-core:build` does TWO deliberately-uncached expensive things:

1. **RC-1 — re-runs `npm install` every build.** `build` `dependsOn:["install"]`; the `install` target (`npm install`, [project.json:8-17]) has NO cache/inputs/outputs → NX always runs it. falcon-ui-core is a NESTED npm project (own **505 MB / 249-pkg** node_modules; `@stencil/core` + its own Tailwind v4/PostCSS toolchain NOT hoisted to root). This is the user's "why is it always installing if installed?" — uncached by config. Fix = freshness-guard (skip if `node_modules/.package-lock.json` newer than `package-lock.json`) or make install cacheable.

2. **RC-2 — Stencil rebuilds COLD + single-threaded + uncached (~98s measured, 110 .tsx components).** 3 stacked workarounds: (2a) [build.cjs:20-23] deletes the **44MB `.stencil` incremental cache** every build → always cold (the "would overwrite input file" error it guards is really stale `dist/types`, not `.stencil` → clean ONLY dist/types, keep .stencil → ~98s→~10s); (2b) [stencil.config.ts:26] `maxConcurrentWorkers:1` for Windows EMFILE — but Tailwind **v4 Oxide removed that failure mode** (config comment lines 2-3,57-60) + **0 EMFILE in all logs** → can raise workers; (2c) [project.json:28] NX `cache:false` for a past cached stub-corruption — `verifyNoStubsRemain()` ([build.cjs:91-110,115,121]) now runs before EVERY exit-0 (incl EMFILE-partial path) so corruption can't be cached, BUT enabling `cache:true` is NOT a one-line flip (VALIDATION 2026-06-03): the Stencil build ALSO writes `../falcon-ui-react/src` + `../falcon-ui-vue/src/index.ts` ([generate-vue-proxies.cjs:21]) + `web-types.json` and EDITS `package.json` (web-types field — an INPUT) ([generate-web-types.cjs:213-221]) → declare ALL outputs (incl sibling projects) or split the generators out of the cached compile first. P1(keep .stencil)+P2(install-guard)+P3(parallel workers) are the clean wins; P4(cache:true) is Medium-High, do last/separately.

**"Sometimes slow" = [ensure-libs.mjs] sentinel SKIPS the lib build on cache-hit; MISS (lib src edit, npm install, branch switch, clean, or plain `nx build`/`gate:all` not via ensure-libs) = full cold path.** ensure-libs.mjs exists ONLY because the lib is uncached; fixing RC-2 lets most of it be deleted.

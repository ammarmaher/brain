**Bug:** On first login, Email (and Phone) should become Verified. Phone was ALREADY correct (no change needed): `VerifyOtpProcess.cs:38-43` sets Mongo `IsPhoneVerified=true` on SMS/null OTP, and Zitadel verifies phone at user creation (`ZitadelUserService.cs:64-75`). The real gap = **EMAIL**: never marked verified in either store. Email is deliberately left unverified at creation (`ZitadelUserService.cs:23-24,35-39`), and the credentials email is sent at user *creation* (`CreateUserProcess.cs:131-133` → `UserCredentialsGeneratedDomainEvent` → `UserCredentialsNotificationHandler.cs:50`), not after first login.

**Root cause:** `FirstLoginSetupProcess.cs:36-38` (terminal first-login step, Pending→Active) only set `Status=Active` — never touched `IsEmailVerified` nor called Zitadel.

**Decision (user, 2026-06-23):** verify email AT FIRST LOGIN (same point as phone), NOT on 2nd login (there is NO login-count/last-login field in identity, so "2nd login" would need new tracking — rejected). Auto-verify email WITHOUT proof-of-ownership is the intended product rule (flagged; user confirmed).

**Fix (backend-only, 4 files):**
- `FirstLoginSetupProcess.cs` — load user; gate on genuine first login (`Status==Pending`, still Pending at this point so ordinary forced-password-change of an Active user is untouched); best-effort Zitadel email-verify (try/catch, logs warning, never blocks login); set Mongo `IsEmailVerified=true` ONLY when Zitadel succeeded (no DB↔Zitadel drift); skip when no email or already verified.
- `IZitadelVerificationService.cs` + `ZitadelVerificationService.cs` — new `MarkUserEmailVerifiedAsync(userId)` = **resend→verify**: `ResendEmailVerificationAsync` (POST `v2/users/{id}/email/resend` returnCode → fresh code) then `VerifyUserEmailAsync` (POST `email/verify`). ⚠️ FIRST ATTEMPT WAS WRONG: codeless `POST v2/users/{id}/email {email,isVerified:true}` → Zitadel **400 `COMMAND-Uch5e "Email not changed"`** (SetEmail rejects an UNCHANGED address; the `returnCode` shape fails the same way). Resend→verify is the correct path for an existing/unchanged email. Both methods pre-existed.
- `ZitadelIdentityManagerFacade.cs` — delegation (`IIdentityManager` inherits `IZitadelVerificationService`).

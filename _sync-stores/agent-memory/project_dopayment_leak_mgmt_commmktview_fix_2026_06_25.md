**BUG (user-reproduced):** Login SA → CommChannel & Marketplace → select account with a VISIBLE app/channel that has NO price value → actions show NO "Do Payment" (CORRECT). Login AO (Account Owner / Client), same item → "Do Payment" SHOWS (WRONG). Should be hidden unless price value + price type are set, exactly like SA. Affects mgmt-console Marketplace (apps) AND Comms Hub (channels). Continues [[project_service_action_display_model_2026_06_25]].

**ROOT CAUSE (FE-only; backend was already correct):** The two consoles use DIFFERENT shared FE components. ADMIN/SA marketplace = `MarketplaceApplicationsMngComponent` → shared `<app-service-pricing>` → `buildServiceRowActions` `[CODE] libs/falcon/src/shared-features/service-pricing-table/models/table-config.ts:79` gates doPayment = `canPayment && hasAction(DoPayment)` (on backend `availableActions[]`) → correct. MGMT/AO marketplace = `MarketplaceApplicationsComponent` + Comms Hub → shared `<app-comm-mkt-view>` (`libs/falcon/src/shared-features/comm-mkt-view`). Its action catalog `comm-mkt-view.config.ts COMM_MKT_ACTIONS` gated doPayment with `{ kind: 'status' }` → `commMktActionVisible`→`canDoPaymentForStatus(status)` returns true for InActive/Expired/Pending* on STATUS ALONE, ignoring price + availableActions → leak. Single render path: both list kebab (`comm-mkt-view.component.ts:213`) and grid card (`comm-mkt-card.component.ts:297`) go through `resolveCommMktActions`.

**The dev's "BUG-DOPAYMENT" rationale was STALE/FALSE:** they believed the mgmt/Client gateway drops DoPayment from availableActions so couldn't gate on it. But: generator `[CODE] AllowedFalconServiceActionsGenerator.cs:22-37` adds DoPayment for EITHER userType when `HasConfiguredPricing` (PricingType && PriceValue) + status InActive/Expired (no Falcon-only restriction on DoPayment); the mgmt list endpoint `applications/visible/details` + `comm-channels/visible/details` runs the generator with the REAL caller type `[CODE] GetVisibleApplicationDetailsHandler.cs:84`; gateways are YARP passthrough (no body transform); mgmt mapper copies it `[CODE] apps/management-console/.../marketplace-applications/models/models.ts:120 allowedActions = wire.availableActions ?? []`. Backend test even asserts visible-InActive-unpriced → availableActions==[Disable] only (`GetVisibleApplicationDetailsHandlerTests.cs:134`). So `allowedActions` for the AO is correct & reliable; status-only gate was unnecessary and WAS the bug.

**FIX APPLIED (FE-only, 1 file, UNCOMMITTED on polishing-v0.4 per [[feedback_fe_no_commit_no_branch_without_instruction_2026_06_22]]):** `comm-mkt-view.config.ts` — changed doPayment gate from `{ kind: 'status' }` to `{ kind: 'allowedActions', rowAction: FalconRowAction.DoPayment }` (now identical to admin SA path).

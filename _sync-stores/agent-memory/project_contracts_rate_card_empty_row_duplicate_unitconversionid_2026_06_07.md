**Contracts & Cost — admin Rate Card "empty row" + "Showing 0-0 from 0" on edit. TWO distinct bugs, fully root-caused + FIXED + DEPLOYED (2026-06-07, claude). Live UI confirm pending login.**

**SYMPTOMS** (admin-console → Contracts & Cost → edit ANY contract → Rate Card tab): a phantom EMPTY row above the real row; footer reads "Showing 0 - 0 from 0 / 1 of 1". Branch polishing-v0.4.

**BUG A — "Showing 0 - 0 from 0" (separate, was NOT a race symptom).** `<falcon-angular-data-table>` renders an internal custom footer (`showCustomFooter` default true) whose "Showing X-Y from Z" is computed PURELY from `[totalRecords]` ([CODE] `falcon-custom-table-footer.component.ts:49-59`). The wrapper NEVER derived total from `data.length` — `[totalRecords]="totalRecords ?? 0"` and the input defaults `null`→0 ([CODE] `falcon-data-table.component.html:73`/`.ts:219`). Working tables (templates-list, org users) explicitly pass `[totalRecords]`+`[currentPage]`+`(pageChange)`+`(rowsChange)`; the rate-card table (`rate-card-step.component.html`) passes none → total=0. **FIX:** added `effectiveTotalRecords` getter to the SHARED wrapper — `totalRecords ?? (lazy ? 0 : data.length)` — bound it on the footer + Stencil `total-records` attr. Fixes Rate Card + Contract Details + Addons + view panes in BOTH apps at once.

**BUG B — the empty row = DUPLICATE unitConversionId (DATA/BACKEND root, FE fragility).** Inspected `FalconCommerceDB.Contracts` directly (mongo root/example): EVERY contract's `tariffPlan.unitConversions` carry the SAME `unitConversionId` for ALL rows (e.g. "asd"/CTR-6A246077: WhatsApp + Voice both `UC-6A256962` — exactly the DevTools `data-row-id`). FE `mapUnitConversion` sets `clientId = unitConversionId` → both rows get one clientId → data-table `dataKey="clientId"` + Strategy-E view registry key `${clientId}::${field}::${kind}` COLLIDE → the shared projected `EmbeddedView` is `replaceChildren`-re-parented into the LAST duplicate `<td>`, leaving the FIRST row's cells EMPTY; `findRowById` first-match shows one row's data twice (Voice never renders); `sameRow()` would patch BOTH on edit. **BACKEND ROOT:** [CODE] `CreateContractHandler.cs:154/167/177/192` + `UpdateContractHandler.cs:81/94/104/119` mint `$"{PFX}-{ObjectId.GenerateNewId().ToString()[..8].ToUpperInvariant()}"` — the first 8 hex of a Mongo ObjectId are the TIMESTAMP (whole seconds), so every id minted in the same request/second is IDENTICAL (RateId/UnitConversionId/QuotaId/OverageRateId all collide intra-contract). **FIXES:** (1) FE chokepoint `createDefaultUnitConversions` (admin+mgmt twins `contracts-display.models.ts`) now scopes clientId by the per-row catalog code: `clientId = existingRow.unitConversionId ? \`${unitConversionId}-${normalizeCatalogKey(code)}\` : prior` — unique + stable + idempotent; clientId is FE-LOCAL (save sends conversions by `code` only — `toUpdatePayload` — never clientId/id, so safe). (2) Backend: removed `[..8]` → full ObjectId (unique) on all 8 mints in both handlers.

**WHY the prior "single-write" fix (HEAD 91f42b7d, your 14:39 commit) did NOT fix it:** it removed the prefill double-write N→M shrink (a real but DIFFERENT race) — its comment wrongly blamed the 0-0-0 footer on that race.

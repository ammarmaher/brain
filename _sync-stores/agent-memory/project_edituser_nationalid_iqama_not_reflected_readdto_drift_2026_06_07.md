**Edit User — IqamaID (NationalId) "saves successfully but not reflected" — ROOT-CAUSED + FIXED** (claude, 2026-06-07, branch of `falcon-core-identity-svc`, NO commits).

**Symptom (user report):** editing IqamaID on the Edit User page → Save toast = success, but the value reverts/blank on the refreshed form.

**Root cause = read-path DTO drift, NOT a write bug.** The WRITE path is fully correct end-to-end:
- FE template `[CODE] libs/falcon/src/shared-features/user-details/components/user-details-page.component.html:444` binds `nationalId` + `(ngModelChange)="onFieldChange('nationalId',$event)"`.
- FE save `[CODE] .../user-details/signals/signals.ts:806` puts `nationalId: next.nationalId ?? ''` into `UpdateUserProfileRequest`.
- FE gateway `[CODE] apps/host-shell/.../core/user/user-api.service.ts:187` → `PUT identity/user/{id}/profile` forwards the full body untouched.
- BE DTOs all carry it: `UpdateUserProfileByIdRequest.NationalId` `[CODE] Application/Users/Models/UpdateUserProfileByIdRequest.cs:21`, `UpdateUserProfileCommand.NationalId:23`, Mapperly `CommandMapper.cs:44` maps Id→UserId (rest 1:1 incl NationalId).
- BE handler **does persist it**: `[CODE] Application/Users/UseCases/UpdateUserProfileHandler.cs:52` `if (command.NationalId is not null) b.Set(u => u.NationalId, command.NationalId)`. Entity `[CODE] Domain/Entities/User.cs:21-22` `[BsonElement("nationalId")] public string? NationalId`. **→ value IS written to Mongo (that's why Save = success).**

**The break = the GET response dropped it.** `[CODE] Application/Users/Models/UserResponse.cs` had NO `NationalId` property and `[CODE] Application/Mappers/UserMapper.cs MapToResponse()` never mapped `user.NationalId`. Both GET paths use it: `GetUserByIdEndpoint.cs:36` (admin edit) + `GetMyProfileEndpoint.cs:24` (self /profile). So the post-save refetch returned no `nationalId` → FE `mapUserResponseToUser` `[CODE] user-details.models.ts:123` `r.nationalId ?? ''` → '' → "not reflected." FE SDK `UserResponse` `[CODE] libs/sdk/src/types/user-details.dtos.ts:29` HAD `nationalId: string|null` (comment even claimed "matching the C# DTOs") → genuine FE↔BE contract drift.

**FIX (2 additive lines, zero-risk):** added `public string? NationalId { get; set; }` to `UserResponse.cs` (after PhoneNumber) + `NationalId = user.NationalId,` to `UserMapper.MapToResponse()`. Fixes BOTH admin Edit User (GET /user/{id}) and self profile (GET /user/me). Added regression test `MapToResponse_ShouldIncludeNationalId` in `tests/.../Application/UserMapperTests.cs`.

Contract LIST table column-width + overflow-ellipsis polish (2026-06-06, claude). User ask: contract-list columns should have controlled/consistent widths like the screenshot, and when text exceeds a column it should show "…" + a hover tooltip with the full value. Apply in BOTH admin + management consoles, follow FE structure/theming + component-edit rules.

**Feature = the contract LIST** rendered by `<falcon-angular-data-table>` (Strategy-E projection over Light-DOM Stencil `<falcon-table-tw>`) in `apps/{admin,management}-console/src/app/features/contracts-cost-management/contracts-cost-management.component.{ts,html}`. Columns are defined in `columns()` (TS) as `ColumnDef[]`; cell CONTENT is projected via `<ng-template falconDataTableCell="<field>">`.

**Why ellipsis wasn't engaging before:** `[CODE] libs/falcon-ui-core/src/tailwind/table-tailwind-classes.ts falconTableClasses()` returns `'w-full min-w-max border-collapse'` (NO `table-fixed`; `min-w-max` = `min-width:max-content`). So a column's declared `width` is only a MIN/preferred in auto-layout — a long contract name grows the column / scrolls the table instead of truncating.

**Chosen mechanism (feature-only, NO shared Stencil edit — lowest risk):** cap the two free-text columns with **`maxWidth` == `width`** on the ColumnDef. `ColumnDef` already supports `maxWidth` (`adaptColumns` maps it → `FalconTableColumnExt.maxWidth` → Stencil `cellWidthStyle()` applies inline `max-width` to BOTH `<th>`+`<td>`). Per CSS intrinsic-sizing, a cell's **max-content contribution is clamped by its `max-width`**, so `min-w-max` resolves to the CAPPED width — the column can't grow past the cap even with a long name. Then the cell template wraps content in an inner `<span class="block truncate …">` (Tailwind `truncate` = overflow-hidden+ellipsis+nowrap; the block span fills the capped `<td>` content box → clips to "…"). REJECTED `tableStyleClass="table-fixed"` because the Stencil-added Actions column has no width → under fixed layout it would balloon to absorb all extra width on wide screens.

**Tooltip = NEW shared directive** `FalconOverflowTitleDirective` (selector `[falconOverflowTitle]`) at `libs/falcon/src/shared-ui/lib/directives/falcon-overflow-title.directive.ts`, exported via the directives barrel → `@falcon`. Sets the native `title` attr ONLY when the host is actually clipped (`scrollWidth - clientWidth > 1`), measured lazily on `mouseenter`/`focusin` (settled layout, async-data-safe, RTL-safe). WIDTH-based, never mutates textContent — distinct from the EXISTING char-count `FalconTruncateDirective` (which cuts at N chars + mutates textContent → wrong for this). Pattern mirrors existing `truncate`+`[title]` usage in `user-details-page.component.html` / `falcon-tree-panel`.

**Files (6):** NEW `falcon-overflow-title.directive.ts` + barrel `directives/index.ts`; admin `contracts-cost-management.component.{ts,html}`; mgmt `contracts-cost-management.component.{ts,html}`. Admin already had `width` on all 9 cols → ADDED `maxWidth:'220px'`(contractName)/`'160px'`(farabiReferenceId) + import directive + inner `block truncate` spans + `[falconOverflowTitle]`. Mgmt had NO widths → ADDED the SAME width set as admin (id130/name220+max220/ref160+max160/3×date140/value150-right/remaining150-right/status124) + directive + truncate spans. Truncation applied to **contractName + farabiReferenceId only** (the realistic overflow columns; id/date/money/status are short fixed-format). Column `width`/`maxWidth` are string px in the .ts CONFIG (component inputs, like the pre-existing admin widths) — NOT Tailwind class literals, so not a tokenization-rule violation.

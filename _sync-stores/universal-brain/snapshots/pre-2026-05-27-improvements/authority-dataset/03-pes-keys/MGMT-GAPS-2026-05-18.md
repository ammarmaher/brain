## Backend coordination required (DO NOT skip)

Per `[BRAIN-OUT] 11-copy-playbook/copy-admin-feature-to-mgmt.md` Step 11, each new resource needs:

1. **`BuiltInRoleCatalog.cs`** — add `BuiltInPolicyRuleDefinition` for each acc-* role's verdict:
   - `acc.wallet/view` — allow for acc-owner; deny for acc-admin + acc-user
   - `acc.wallet/transfer` — allow for acc-owner; deny for acc-admin + acc-user
   - `acc.organization/edit` — allow for acc-owner + acc-admin; deny for acc-user
   - `acc.user/add` — allow for acc-owner; allow for acc-admin (limited to non-acc-owner targets per role-edit matrix)
   - `acc.user-permission-group/assign` — same as user/add
   - `acc.user-profile-picture/upload` — same as user/add

2. **`pes-account-role-rules.json`** — add tenant-scoped p-rules mirroring above

3. **`seed-test-users.sh`** — verify all 3 acc-* test users still satisfy the link

4. **Restart Identity** to pick up catalog changes

## Workaround for night-shift execution (Wave 11+ depending on these)

- **Wave 8 (Add User wizard)** — fall back to: gate by `managementConsole.accountUser.add` (root context) + `managementConsole.orgUser.add` (sub-node context). Both ALREADY exist in registry. This is sufficient for the wizard mount; the per-step keys (perm-group, photo) gate inner controls — until those exist, render the controls unconditionally and rely on backend rejection.
- **Wave 10 (Edit Node)** — reuse `managementConsole.organization.add()` for now (rename is conceptually under "modify org").
- **Wave 11 (Wallet)** — gate entirely by route-level `managementConsole.account.view()` + server-driven `canSave`. Document the decision in the wave commit.

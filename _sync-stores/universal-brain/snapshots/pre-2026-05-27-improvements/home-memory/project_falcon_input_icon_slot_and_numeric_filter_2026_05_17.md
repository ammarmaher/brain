## Bug class fixed at root

1. **Icon-left invisible**: Stencil `shadow:false` host defaults to `display:inline` → `:host{display:block}` fix per workspace trap rule 1. Plus hardcoded `text-falcon-neutral-700` color in old wrapper replaced with token-driven `var(--falcon-input-icon-color)` = `#6b7280`.
2. **Letters accepted by integer input**: previous defence was only `type="number"` + `inputmode="numeric"` which the browser doesn't fully enforce. New DOM-level keystroke + paste + beforeinput filter blocks every non-digit (except `.` when decimal allowed, `-` when negative allowed at position 0).
3. **iconLeftSvg raw-string trap**: required consumers to maintain SVG strings instead of dropping standard Falcon icon components — replaced with slot projection (canonical Angular content-projection contract).
4. **Asymmetric composition**: input-number wrapper used `<falcon-angular-input>` instead of `<falcon-input-tw>` directly — broke `[disabled]` / value-write parity at multiple points. Now matches the 8 other form-control wrappers.

## Canonical wrapper pattern (established)

Reference: `libs/falcon-ui-core/src/angular-wrapper/components/falcon-input/falcon-input.component.{ts,html}`.

Shape:
- `@Component({ selector: 'falcon-angular-X', imports: [], templateUrl: ..., schemas: [CUSTOM_ELEMENTS_SCHEMA], providers: [NG_VALUE_ACCESSOR via forwardRef] })`
- `ngOnInit(): void { void defineFalconTwComponent('falcon-X'); }`
- Stencil element ref via `@ViewChild('inputEl', ...)` for defensive `componentOnReady().then(push)` value write
- `disabled` signal + `@Input('disabled') set disabledFromInput(...)` direct template binding parity
- Tag-switcher HTML: `@if (useTailwind) { <falcon-X-tw>...} @else { <falcon-X>...}`
- Both paths get `[attr.icon-left]="iconLeft ? '' : null"` + `[attr.icon-right]="iconRight ? '' : null"` + `[attr.input-mode]="inputMode || null"` + `<ng-content select="[slot=icon-left]">` projection

## Consumer usage

```html
<falcon-angular-input-number
  iconLeft
  [integer]="true"
  [min]="0"
  [ngModel]="row.priceValue"
  (ngModelChange)="setPriceValue(row.id, $event)">
  <span slot="icon-left">
    <falcon-angular-saudi-riyal-icon [size]="14" />
  </span>
</falcon-angular-input-number>
```

The `slot="icon-left"` is REQUIRED on a child element (typically a `<span>`) — Angular's content projection uses CSS-selector matching, not just direct children. Falcon icon components project through transparently.
